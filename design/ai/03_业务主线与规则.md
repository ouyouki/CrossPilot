# 03 · 业务主线与规则

> 本册定义“系统在业务上到底怎么算、怎么拦”。所有数字口径只在这里定义一次；其他册（含画面）只引用，不另立公式。
> 示例数值**仅演示**，不是平台事实。凡标 `U-n` 的是未知外部事实，处理方式见 02 §5。

## 1. 主线总览与状态机

```
[方向卡] ─人给方向─▶ ①选品 ─▶ ★同意1 ─▶ ②采集 ─▶ ③素材工厂 ─▶ ★同意2 ─▶ ④上架 ─▶ 读回 ─▶ LIVE
                      │                       │              │                  │
                      └ G0 品类闸门            └ 货源确认      └ G1–G4 合规闸门     └ 载荷冻结 + 哈希
```

### 1.1 开工前置清单（Readiness）

流水线启动前，系统检查下列 6 项，**任一未就绪 → 流水线不启动**，今日页显示缺哪项、去哪填（这是把“未知即阻断”变成一个可操作的向导，而不是到处出 UNKNOWN）：

| # | 前置项 | 就绪条件 |
|---|---|---|
| 1 | 方向卡 | 有已生效版本，含毛利底线、价格带、至少 1 个白名单类目 |
| 2 | 费率卡 | 03 §3.1 所有 BLOCKING 项已填且带来源与日期 |
| 3 | 品类白名单 | 至少 1 条 `ALLOW`，带出处 |
| 4 | 店铺档案 | 特商法表示已确认、运费模板与発送日数已填（U-4/U-7） |
| 5 | 规则库 | 合规规则库有已发布版本且未过期（04 §3） |
| 6 | 模型预算 | 每日预算上限已设（未设 = 0 = 不生成） |

### 1.2 候选/商品生命周期（单一状态机，代码里是一张转换表）

```
NEW ─▶ SCORED ─┬▶ BLOCKED_G0（不可售，不可勾选）
               ├▶ NEEDS_DATA（利润/必填信号不可算，进缺口队列）
               └▶ READY（利润可算：允许估算值，显示区间）─▶ SELECTED（同意1通过）─▶ SOURCING（确认采：采购价/重量等换成 CONFIRMED 值；样品/授权）
                      ─▶ SAMPLE_PENDING（样品在途，可选，不计入挂起告警）─▶ SOURCED（货源确认完成）
                      ─▶ CREATING ─▶ CHECK_FAILED(可重试≤N，超限 HELD) ─▶ CHECKED ─▶ AWAITING_CONSENT2
                      ─▶ APPROVED ─▶ LISTING_PENDING ─▶ SUBMITTED ─▶ PLATFORM_REVIEW
                      ─▶ LIVE | PLATFORM_REJECTED(→CREATING，带驳回原因) | READBACK_MISMATCH(HELD)
LIVE ─▶ DELISTED（人工下架/平台下架，记录原因）
任意状态 ─▶ DROPPED（人放弃，必填原因，原因入语料库）
```

**补充边（评审后）**：`NEEDS_DATA ↔ READY`（补齐数据后进入、数据过期退回）；`BLOCKED_PRICE`（无满足底线的价）；同意 2 的 RETURN → `CREATING`、REJECT → `DROPPED`（可恢复）、VOID → 回流水线重判；`READBACK_MISMATCH → SUBMITTED（改后重填一致）| DELISTED`；`EXECUTED_STALE`（04 §5.2）；**LIVE 不可直接转 DROPPED**，只能经 `DELISTED`；“待法务”是 HELD 的一种原因（`held_reason='LEGAL_REVIEW'`），在待批页“挂起”页签可见。

**两段式货源（F-01）**：同意 1 之前是**预采**——每个候选只需要“参考货源链接 + 参考价 + 估重/估尺寸”（`status=ESTIMATED`，来源写明，可由人录入或贴链接），系统据此算出**利润区间**（估值上下各浮 `estimate_margin_pct`，缺省 15%，只能加大）；同意 1 之后是**确认采**——换成 `CONFIRMED` 值，PC-COST 以确认值重算，毛利跌破底线则该品作废回到候选。ESTIMATED 值在“选品排序/同意 1”算**已知**，在“同意 2/上架”算**缺失**（必须 CONFIRMED）。预采所需人时计入 02 §3 的人时指标。

规则：转换只能沿表上的边发生；`HELD` 是叠加标记（不是状态）：表示“等人”，不改变所在状态，不过期。

## 2. 选品（CAP-CAN / CAP-INT / CAP-DIR）

### 2.1 方向卡（人给方向）

| 字段 | 类型 | 说明 |
|---|---|---|
| `categories` | 白名单类目子集 | 只能从 G0 白名单选 |
| `price_band_jpy` | 区间 | 税込售价带 |
| `margin_floor` | 百分比（**必填**） | 毛利底线，低于此的候选不进入 READY；未填 = 不开工（NV-8）；**降低它属于放宽，24 小时后生效** |
| `margin_target` | 百分比 | 缺省 = 底线 + 20pp，用于利润分归一 |
| `daily_candidates` | 整数 | 每日候选上限（默认 30） |
| `selection_cap` | 整数 | 同意 1 单批最多勾选数（默认 10） |
| `avoid` | 关键词/品牌列表 | 命中即不入候选 |
| `weights` | w1..w4（基点整数，和=10000；界面按百分比显示） | 需求/利润/竞争/风险权重，默认 3500/3500/1500/1500 |
| `season_focus` | 节庆列表 | 可选 |
| `max_ship_share` | 百分比 | 国际运费÷售价的警告线（缺省 20%，仅警告） |

每次保存生成新版本；候选、审批单都固定引用当时的版本号。方向卡是人自己的输入，版本化、可回看差异；**收紧即时生效，放宽（降毛利底线、加类目、提价格带上限）24 小时后生效**（统一的“放宽”判据：这次变更会让更多对象通过，见 04 §8）。

### 2.2 输入信号（任一信号必须能追到来源）

| 信号 | 获取方式（P1） | `source_grade` |
|---|---|---|
| 榜单/商机/价格带/竞品在售 | 卖家后台导出 CSV；表格粘贴；第三方分析工具 CSV；截图识别（需人确认） | A=官方导出 / B=第三方导出 / C=截图识别或手录 |
| 货源价/起订/发货地 | 人贴链接 + 填字段（CAP-COL-01） | 人录入视为 B；附截图为 A |
| 汇率 | 费率卡（人维护，每日一次，带来源与时间） | — |

**红线**：不抓取平台页面、不模拟登录、不绕过验证码（NV-5）。导入文件解析失败就明说“请人工修正第 N 行”，不猜。

### 2.3 打分（唯一公式）

```
score = 100 × ( w1·demand + w2·profit + w3·competition_gap ) − 100 × w4·risk   （demand/profit/competition_gap/risk 均在 0–1）
```

| 项 | 定义 |
|---|---|
| `demand` | 导入榜单内的排名分位（越靠前越高）与近期增长、达人带货数的加权；至少 1 条 `source_grade ≥ B` 的需求信号，否则 `demand=UNKNOWN` |
| `profit` | `clamp((margin − margin_floor) / (margin_target − margin_floor), 0, 1)`；margin 来自 §3（预采阶段用估值区间的**下沿**），`UNKNOWN` 则不进排序；候选卡另显示“首批资金敞口 = MOQ × c1”（仅展示） |
| `competition_gap` | 1 − 竞争强度（同类在架数分位、头部评价数分位）；缺失时记 0 并打 DEGRADING 标记 |
| `risk` | 0–1：合规预筛 WARN 数、品牌/IP 疑似、运费占比超线、节庆错配、数据新鲜度低 的加权，权重在配置里，可见 |

约束：

- **BLOCKING 缺失**（利润分子的任一成本项/汇率/税口径，或 G0 属性未知）→ 候选进 `NEEDS_DATA`，**不显示分数**。
- **DEGRADING 缺失**（竞争数据、季节标注）→ 可排序，但总分扣减 ≤ 30 分，行上显示“数据不全”，且批量勾选时必须逐行展开确认。
- 排序**只有这一套公式**；任何页面的“综合分”都复用，不另造连乘式。
- 每条候选给**一句话理由**：由结构化事实模板生成，LLM 只负责润色；系统校验句中数字与事实一致（不一致则回退模板句）（RL-3）。
- 数据缺口队列显示“补哪一项可解锁几个候选”（CAP-CAN-06）。

### 2.4 G0 品类准入闸门（白名单，默认拒绝）

> 平台跨境店禁限售原文未取得（U-5）。因此 G0 是**白名单**：没登记的类目不可选。

数据：`category_rules(category_path, status ALLOW|DENY, evidence_url, evidence_file, fetched_at, reviewer)`。

判定（确定性）：

1. 类目不在白名单 → `BLOCKED_G0`（理由：未登记）。
2. 命中风险关键词词库（`risk_attribute_lexicon`，保守黑名单，只能更严）→ 设相应属性旗标：`has_battery`、`has_radio`（含蓝牙/无线）、`pse_target`、`cosmetic_or_quasi_drug`、`food_or_supplement`、`food_contact`（器具/容器包装；食品衛生法的适用需核实，**默认 DENY**，放行需附检测报告）、`child_product_or_toy`、`strong_magnet`、`blade_or_sharp`、`laser`、`carrier_restricted`（液体/粉末/喷雾/带磁等承运商禁运，来源=承运商清单）、`alcohol_tobacco`、`medical_device`、`brand_ip_suspect`。
3. 任一旗标为真 → `BLOCKED_G0`，除非白名单条目**显式**写了 `allow_with_flag=<旗标>` 且 `evidence` 非空（例如已取得相应资质）。
4. 白名单类目的 `attribute_confirm_required=true` 时，采集阶段（CAP-COL-05）人必须逐项确认上列旗标（至少：电池、无线、食品接触、儿童用品、强磁、刃物、承运商禁运），缺失 → 阻断到 `SOURCED`。榜单 CSV 的类目与平台类目树需经**类目映射**（导入时确认），映射不上的进 NEEDS_DATA。新增 `ALLOW` 条目本质是放宽，走 ACT-LOOSEN-RULE（24 小时后生效）。
5. 手工改类目会**重跑 G0 并留痕**，不能靠改类目绕过。
6. 上架清单生成时 G0 **再跑一次**；任一 SKU 命中 → **整张上架单不可执行**（不是单行置灰）。

初始白名单由 Owner 按卖家中心类目规则逐项录入，附截图出处；设计不预置任何类目（避免替人下结论）。**提示**：化妆品、医药部外品、食品、酒类、医疗器具、带电池/无线/PSE 的电器在跨境直邮下是否可售未核实，默认 DENY。

## 3. 到岸成本与利润（唯一口径）

### 3.1 费率卡与成本项

费率卡 `rate_card` 按版本保存；每个值带 `value`、`unit`、`source`、`fetched_at`、`status ∈ CONFIRMED | ESTIMATED | MISSING`。

| 项 | 公式（单件，JPY；汇率按 `fx_rate` 快照） | 缺失级别 |
|---|---|---|
| c1 采购价 | `purchase_cny × fx` | BLOCKING |
| c2 国内段运费 | `domestic_ship_cny × fx` | BLOCKING |
| c3 国际运费 | 按重量/体积档位查 `intl_ship_table` | BLOCKING |
| c4 关税 | 按 `tax_regime` 与税率表（需 HS 编码或简易税率分类，`source_items.hs_class`）；`tax_regime=UNKNOWN` → 不可算 | BLOCKING |
| c5 输入消費税 | 由 `tax_regime` 固定决定（见下）；1 万日元门槛按**每票货物的课税价格**判断，需配置 `assumed_units_per_order`，越过门槛按一般课税 | BLOCKING |
| c6 通関费 | 按票/按件分摊（费率卡） | BLOCKING |
| c7 包材 | 按件 | BLOCKING（可显式填 0 并标“已确认为零”） |
| c8 平台佣金 | `commission_rate × commission_base`；`commission_base` 的口径（是否含税、含运费）写在费率卡 `commission_base_rule`，来源平台费率页 | BLOCKING |
| c9 支付/跨境履约手续费 | `rate × base`；若平台说明已含在佣金内，填 0 并附来源 | BLOCKING |
| c10 退货损耗（期望值） | `r × ( R + L − ρ×c8 − (1−u)×c1×[return_mode=RETURN_TO_CN] )`；r=退货/退款率，R=本件营收，L=退运费（仅 RETURN_TO_CN），ρ=佣金随退款返还比例（需核实，缺省 0），u=不可再售比例，`return_mode ∈ {RETURN_TO_CN, DISPOSE_JP, REFUND_ONLY}`（未定=BLOCKING，U-8） | BLOCKING |
| c14 结算换汇/提现手续费 | `rate × revenue`（费率需核实） | BLOCKING（可显式 0） |
| c15 发出件损耗（丢件/破损/拒收） | `loss_rate × (c1+…+c7)` | BLOCKING（可显式 0） |
| c16 样品与拍摄摊销 | `sample_cost ÷ 预计销量`（走 SAMPLE_PENDING 路径时） | 可 0 |
| c11 达人佣金 | 默认 0（显式确认） | 可 0 |
| c12 广告摊销 | 默认 0（显式确认） | 可 0 |
| c13 活动/券分摊 | 默认 0（显式确认） | 可 0 |

```
revenue = ( P + buyer_shipping_fee ) ÷ (1 + 销项消费税率  仅当 tax_regime 规定卖家负担销项税，否则 1)
profit  = revenue − ( c1 + c2 + … + c16 )   （c10 已是期望值，含退款对营收的扣减）
margin  = profit ÷ revenue
```

**`tax_regime`（单一枚举，互斥，取代拆开的两个参数）**：`DE_MINIMIS_EXEMPT`（少額輸入免税适用）/ `SELLER_IOR_DDP`（卖家为输入者）/ `SELLER_LIABLE_LOW_VALUE`（低价值货物由销售者负担消费税）/ `PLATFORM_COLLECTS`（平台课税）/ `UNKNOWN`。每个值固定对应 c4、c5、销项税的处理，不会重复扣或漏扣；带 `effective_from/to`，到期或口径变更（日本 2026 年度税制改正涉及越境 EC 的少額輸入免税与平台课税，**施行日与适用对象需核实**，U-3b）触发前置失效 PC-TAX（属事实失效，不是审批过期）。`ASSUMED_WORST` 见下。

**最坏情形假设（F-06）**：外部答复未到时，Owner 可选择 `ASSUMED_WORST`——关税与输入消費税与销项税均计、退货率取上限、佣金取已知最高档；必须写理由并进审计，利润标 `ASSUMED`；**只能更严，不能用来放宽**，且不得进入授权清单代批。

- **每项只扣一次**。到岸成本是 c1–c7 的小计；佣金与退货损耗单列，**不得再并入到岸成本**（修正 DeepSeek 版的重复扣减，见 ADR-09）。
- `P` = 税込售价。候选阶段用价格带中位或方向卡价格；同意 2 时用最终价。
- **缺任一 BLOCKING 项 → `profit = UNKNOWN`，不给金额也不给分数**，且不得用默认值补（INV-10）。
- 利润界面必须能展开全部分项，并显示每项的来源与新鲜度。
- 汇率：**自动获取**（13 号册 §3.3），`fx_rates(pair, rate, ref_date, source_id, fetched_at, raw_hash)`；审批快照引用 `fx_rate_id`。偏离快照 >3%（可配，只能收紧）→ 审批单前置失效（04 §5）。
- 运费占比 `c3 ÷ P` 超过 `max_ship_share` → 风险项（仅警告）。
- 所有税务数据仅供测算，不作申报依据（NV-1）。

### 3.2 定价建议（同意 2 的一部分）

系统给**建议售价**：满足 `margin ≥ margin_floor + price_safety_margin`（安全边际，缺省 3pp，只能加大，避免汇率小幅波动即触发作废）的最低整数价，并落在竞品价格带内；若不存在这样的价 → 该品 `BLOCKED_PRICE`（不进同意 2）。**售价低于“成本地板价”（利润=0 的价）在引擎层 BLOCK**，不可被批准。最终价由人在同意 2 批准；批准后改价 = 变更重批（INV-14）。

## 4. 采集（CAP-COL）

### 4.1 采什么、怎么进

货源页字段：标题、图片、规格/尺码、价格与阶梯价、起订量、重量与体积、发货地、**供应商发货时效（天）与集货时效（天）**、品牌/授权信息、HS 分类、属性旗标（见 §2.4）。

**时效与库存硬判定（F-14）**：`供应商发货 + 集货 ≤ shop.dispatch_days − 缓冲` 不满足 → BLOCK；`initial_stock` 超过已备货量或供应商确认可供量 → WARN。`dispatch_days` 是店铺单值，多货源时**以最慢货源为准**。

**现实路径（F-11）**：1688 供应商多数不出书面授权、供应商图本身可能盗图，实务做法是**买样品自拍**——状态 `SAMPLE_PENDING`，样品与拍摄成本摊入 c16；`supplier_license` 须带“授权链声明”字段（授权方是否为权利人）。

进入方式：**人贴链接 + 人填字段 + 上传图包**（P1）。系统不抓页面。链接为空不给补录入口（来源可追溯）。

### 4.2 图片授权（红线）

每张图必须带 `license_type`：

| 值 | 含义 | 可进入素材生成 |
|---|---|---|
| `own_shot` | 自有拍摄 | ✅ |
| `supplier_license` | 供应商书面授权（附证据） | ✅ |
| `brand_owner` | 品牌方授权（附证据） | ✅ |
| `ai_from_own_photo` | 以自有实拍为底图的 AI 加工 | ✅（见 AIGC 等级） |
| `none` | 无授权（仅内部比对价格/规格） | ❌ 进入生成管线即 BLOCK（U-9） |

**非图片素材也要授权登记（F-10）**：BGM、字体（图片文字层）、TTS 声音须登记在 `asset_licenses(kind ∈ audio|font|voice, license, evidence)`，模板只能引用已登记资源；G3-007：引用未登记资源即 BLOCK。

禁止：搬运竞品图、去水印后使用、以未授权图做二次创作。素材审批界面必须能**并排看到派生图与依据图**及授权证据。

### 4.3 采集箱处理

去重（同源 SKU 一条，其余标“同源”）→ 品牌/IP 初筛（命中打“需人工确认”）→ 属性旗标人工确认 → 货源确认清单（有货、起订、发货时效、授权、质量风险自检）全部勾选 → `SOURCED`。抓不到/缺字段 → 明说“请人填哪些字段”，不猜。

## 5. 素材工厂（CAP-AST）

### 5.1 交付物与规格

> 规格数值来源：DeepSeek 版整理的平台商品登记规则（抓取日期 2026-10-19，**官方原文待复核**）。落地时以 `market_profile.asset_spec` 配置为准，配置为空则 G4 阻断（U-11）。

| 素材 | 规格 | 生成方式 |
|---|---|---|
| 日文标题 | 字符上限取配置；含目标搜索词；无禁用表达 | LLM + 词库 |
| 卖点 | 5 条，每条 ≤40 字 | LLM |
| 介绍页 | 卖点/规格/用法/注意/配送/原産国 结构化长文 | LLM + 模板 |
| 主图/商品图 | 合计 **≤ 9 张**（白底主图、卖点图、规格图、场景图、包装/配件图，同一个池子）；JPG/PNG；每张 ≤5MB、≥300×300 | Pillow 本地渲染 |
| 竖版视频 | 1 条；MP4、≤10MB、<60 秒；9:16；15–30 秒；图片轮播 + 日文字幕 + 配音(可选) + 免版权音乐 | 本地 ffmpeg 模板，码率上限保证 30 秒 ≤10MB |

张数契约：生成侧按 9 张上限分配位次，超出报错，**不静默截断**。第一阶段不调用按条计费的 AI 视频生成。

### 5.2 AIGC 等级与使用

| 等级 | 定义 | 规则 |
|---|---|---|
| L0 | 实拍原图，仅裁剪调色 | 全部位置 |
| L1 | 实拍原图 + 背景替换或日文信息层 | 主图、商品图、场景图；`asset_items` 记录 AI 处理痕迹，是否需画面标注按 U-10 答复决定（答复前背景替换图不标但必须登记） |
| L2 | AI 生成的场景/模特 | 仅当以该 SKU 实拍图为底图且商品本体像素与比例未被改动；否则不得用于主图/商品图；**画面一律标注“AI生成”**（取 U-10 最严口径）；WARN（同意 2 逐项确认）；**AI 生成的人物（模特）在 U-10 答复前禁用于主图** |
| L3 | AI 配音/AI 头像 | 仅短视频；**画面必须带“AI生成”字样**（模板自动加，缺失 BLOCK） |

禁止：AI 生成/模仿真人、名人、医生、公职人员形象与声音；通过素材改变尺寸、虚构功能或附属品；前后对比图、医疗场景图（模板库中不存在这些模板）。每个素材带 `perceptual_hash`，与本店已有素材近似度超阈值（缺省 0.9，需实测校准）→ BLOCK；比较时**排除同一候选的历史版本和同一 `base_image` 派生的图**，否则 v2 会永远 CHECK_FAILED。

### 5.3 合规闸门 G1–G4（确定性，命中 BLOCK 不进待批队列）

G2 匹配前先做**规范化**：NFKC、假名统一（片/平）、去除插入的空格与符号，并用变体生成器测试（“シ ミが消える”“ｼﾐが消える”“しみが消える”）。读回比较同样先做 NFC 与空白规范化（〜 U+301C 与 ～ U+FF5E、全/半角空格、换行），规范化造成的差异单独显示，避免假 MISMATCH 让人养成直接“接受”的习惯。

规则存于 `compliance_rules`，每条另声明 `requires_facts`（评估为三值，缺事实即 UNKNOWN→HOLD），每条必带：`rule_id`、`scope`、`pattern`（正则/词表/函数名）、`severity (BLOCK|WARN)`、`rewrite_hint`、`source`（官方条文/平台页面/内部保守规则）、`verified`（`VERIFIED|UNVERIFIED`）、`effective_from`、`version`。**`UNVERIFIED` 的规则只允许更严（BLOCK 或 WARN），不允许用来放行；放宽任何规则需 Owner 批准 + 出处（ACT-LOOSEN-RULE）。**

| 层 | 规则 | 说明 |
|---|---|---|
| G1 上架必备表示 | RULE-G1-001 特商法表示已确认（店铺档案）；-002 送料已填（买家付金额或卖家承担，二选一，不可为空）；-003 発送までの日数已填（U-4）；-004 返品条件已填（U-8）；-005 原産国已填；-006 税込総額表示 | 缺项 BLOCK |
| G2 文案 | -001 功效/医疗暗示词库（薬機法型表达，如“治る”“シミが消える”“若返る”）；-002 最上級・No.1・絶対・100% 等，无证据记录 BLOCK，有证据降 WARN；-003 **一律不生成划线价**（新建商品没有过去销售实绩），出现二重価格表示即 BLOCK，无“有依据降 WARN”通道；-009 **原産国誤認**：中国产品的日文页面/图片出现“日本製”“日本品質”、日本国旗、仿国产包装语即 BLOCK；-010 健康类暗示词库（“肩こり解消”“姿勢矯正”“デトックス”“ウイルス除去”等，薬機法/景表法）BLOCK；-011 **简体字形混入**检测（日文字段出现日文不用的简体字形）BLOCK；-004 ステマ：自营素材不得伪装第三方评价/口碑/用户声音，不得生成诱导好评；-005 数字与规格断言须在 `source_items.attributes` 中有来源（claim-evidence 映射）；-006 品牌/IP 词；-007 宗教民族敏感表达；-008 机翻腔（LLM 提示，仅 WARN，不可放行/不可降级） | BLOCK/WARN |
| G3 图片视频 | -001 `license_type=none` 进入管线 BLOCK；-002 AIGC 等级与“AI生成”标注；-003 水印/竞品 logo/二维码/账号名（OCR+检测，疑似 → BLOCK，人只能重做素材）；-004 人脸出现 → WARN（需确认肖像授权）；-005 近同一素材；-006 认证标志误用；-007 引用未登记授权的 BGM/字体/TTS 资源 | BLOCK/WARN |
| G4 平台规格 | -001 张数 ≤9、尺寸/大小/格式；-002 视频规格；-003 标题/卖点字符上限；-004 类目与必填属性齐全 | BLOCK |

处置：

- **BLOCK**：素材集状态 `CHECK_FAILED`，附命中规则、命中片段、改法；Creator 在重试上限（缺省 3）内改写并复检；超限 → HELD 并交人（人只能改文案/换图并重走复检，**没有“忽略”按钮**）。需要法务判断的，转“待法务”队列（挂起）。
- **WARN**：进入同意 2，必须逐条勾选“已确认”并选预定义原因；确认记录入审计并纳入周抽检。
- 每次校验留痕：规则编号、版本、命中片段、校验时间。

### 5.4 日语质量与中文回译

操作者读中文，不能凭语感核对日文，所以每个文案字段必带：**日文原文 + 中文回译 + 术语一致性标记**。流程：生成 → G2 确定性校验 → LLM 自然度检查（只出 WARN）→ 回译（LLM）→ 术语表检查（税込、送料、原産国等固定译法）。回译只用于帮人读懂，不参与判定。补偿措施（F-16）：回译**换用与生成不同的模型**并要求逐句直译；日文字段的简体字形混入由确定性规则 BLOCK（G2-011）；数字/单位与 `source_items.attributes` 一致性（G2-005）扩展到图片文字层 OCR，图片文字也出回译；每周抽检卡含“母语者抽检 N 条”（可外包），结果回灌词库，抽检人登记在审计。

风格：通贩页面用です・ます；注意事项用简洁体；尺寸 cm、重量 g/kg；税込表示；节庆表达放进 `season_calendar`。

### 5.5 版本、退回与成本闸门

- 每套素材有版本号；退回需选**预定义原因**（措辞/图片/价格/合规/其他），自由文本选填；原因进语料库，下一版默认规避。
- 已批准素材**不得静默修改**：任一字符/像素变化 → 新版本 → 重走同意 2（INV-14）。
- 生成预算：每日、每品、每套素材的重试次数与费用上限；超限即停，需 Owner 放行（`ACT-RELEASE-COST-GATE`，本期只有 Owner 一个批准人，不设财务共签）。本地合成/模板剪辑边际成本为 0；任何外部模型调用都经 Tool Gate 记入 `llm_cost_ledger`。

## 6. 上架（CAP-LST）

### 6.1 上架载荷（同意 2 批的就是它）

`ListingPayload`（一张单一个动作：**新建商品**。不含改价、改库存、下架等其他动作）：

| 字段 | 说明 |
|---|---|
| `title` / `description` / `bullets[5]` | 日文，已通过 G2 |
| `category_path` / `brand` / `origin_country` | G0 已再跑 |
| `price_jpy`（税込） / `initial_stock` | 初始建档值；**后续改价/改库存不在本系统，去后台** |
| `images[≤9]` / `video?` | 文件名 + 内容哈希 + `license_type` |
| `shipping_fee` | 买家付金额 或 卖家承担（二选一，必填） |
| `dispatch_days` | 発送までの日数（必填，U-4） |
| `return_terms` / `warranty` / `sales_conditions` | 按卖家后台实际表单逐项填写 |
| `package_weight_g` / `package_dims_cm` / `material` / `brand_label` / `attributes{}` | 包裹重量尺寸、材质、品牌写法（无品牌按后台规定写法）、类目必填属性；字段集合以 `market_profile.field_schema`（Owner 按后台实际表单截图录入，U-15）为准，**schema 必填而载荷缺失 → G4 BLOCK**；这些值同样经 G2 与同意 2，**不允许操作者在后台现场补写未经批准的对外内容** |
| `variants` | **P1 仅支持单 SKU**；存在变体（颜色/尺寸各自价格库存图片）→ G4 BLOCK，变体建模完成后再放开 |
| `seller_disclosure_ref` | 指向店铺档案中已确认的特商法表示 |
| `cost_snapshot_id` / `fx_rate_id` / `ruleset_version` / `direction_version` | 事实快照 |

冻结后计算 `payload_hash = sha256(canonical_json(payload))`；批准的是这个哈希。

### 6.2 通道 A：执行清单

1. 系统生成清单：逐字段“复制”按钮、素材包（按 SKU 命名的 zip）、直达后台入口。
2. 人在卖家后台照做，回来**回填后台实际值**：商品 ID、标题、价格、库存、类目、图片数、送料、発送日数（可附截图）。
3. 系统比对：关键字段（标题、价格、送料、発送日数、**类目（不一致即重跑 G0）**、**原産国、返品条件**、图片数、**主图截图（与批准主图做感知哈希比对）**）必须逐项一致；不一致 → `READBACK_MISMATCH`（HELD），人只能“去后台改后重填”或“去后台下架”；仅非关键字段（如后台自动补全的措辞）差异可由 Owner 填理由接受。
4. 一致 → `SUBMITTED`；之后人回填平台审核结果（审核中 / 已上线 / 驳回+原因）。驳回 → `CREATING`（带原因）。
5. 清单末尾固定确认位（CAP-LST-05）：店铺运费模板已核对；（若已开通）加入联盟公开计划并**必填联盟佣金率**（驱动 c11，勾选后 c11 不得为 0）；联盟达人内容须标注广告（ステマ，登记为已知盲区）。上架后系统生成**发布包**（视频 + 日文文案 + 话题词 + ステマ提示），作为“一条提醒 + 一个跳转”，人在 App 内发布后回填视频 ID。
6. 执行人默认 ≠ 批准人；单人运行时标“自批自执”，进审计高危视图。

### 6.2.1 通道 A2：批量上架包（推荐，替代逐项照做）
当天已批准且前置成立的商品进入“上架批次”，按末级类目生成**官方批量模板 + 素材包**，人在卖家后台**一次上传**；后台失败文件回传系统自动解析；上架后人导出“商品导出文件”交给系统，**自动读回**。卖家 SKU = `CP-<候选编号>-<载荷哈希前 8 位>`，读回凭它一一对应。批次只是执行打包，每个品仍有各自的同意 2。详见 13 号册 §2。

### 6.3 通道 B（P1.5，仅接口定义）

同一份载荷由适配器写入平台，写入后自动读回；失败/不一致 → HELD。24 小时内可“一键下架”（补偿动作，`SELLER_DEACTIVATED`；**下架不消除平台违规记录**，所以上线前多看一眼比下架便宜）。

### 6.4 上架后

- 每周体检（CAP-OPS-05）：违规分、迟发率、取消率、保证金可用余额、店铺状态；超阈值 → 提醒。**明示：本期不自动读取这些指标，是盲区；不得用“0 违规/正常”暗示健康。**
- 结果回填（CAP-OPS-06）：上架后 ≥7 天由人导入曝光/点击/成交 CSV → 命中率视图 → 权重**校准建议**（采纳需人批）。回填字段：曝光、点击、成交、**退款/退货件数、实际结算额、联盟与广告支出**；系统派生 `realized_margin` 并与 `cost_snapshot` 比较，偏差超阈值 → 提醒校正费率卡（人批）。仅使用去标识化聚合数据（件数、金额、SKU、时间），含个人信息的明细不进系统。

## 7. 季节与节庆

`season_calendar` 配置（お正月、バレンタイン、母の日、お中元、お歳暮、ブラックフライデー、年末年始物流停摆）。用于候选标注与风险项（例如临近物流停摆的长时效品打风险分），不作闸门。
