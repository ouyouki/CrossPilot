# 10 · 决策记录（与 DeepSeek 版的差异）

> 原设计（DeepSeek 版 `CrossPilot.zip`）的**产品理念册（product/01）是本设计的唯一源头**，全部保留。下面逐条记录：它的**工程与范围设计**哪些保留、哪些改、哪些舍弃，以及为什么。
> 记号：**保留** / **改** / **舍**。

## 1. 保留（理念与最有价值的机制）

| ADR | DeepSeek 版 | 处置 | 理由 |
|---|---|---|---|
| ADR-01 | “AI 干活，人只批与给方向”；两道同意（SRC-010 / AST-017） | 保留，改名为 ACT-SELECT / ACT-APPROVE-ASSETS | 这是产品核心 |
| ADR-02 | 三条红线（未批不执行 & 审批不过期；Agent 默认无批准权、授权清单四铁律；判定由确定性规则） | 保留，全部落成 INV 测试 | 原稿也承认“理念 ≠ 实现”，所以把每条钉成不变量 |
| ADR-03 | 9 条不做（不动资金、不做税务申报、官方接口才可访问平台…） | 保留，落成 NEVER 注册 + CI 断言 | “功能压根不存在”比“有按钮要双签”安全一个量级 |
| ADR-04 | 语义参数包哈希 + 事实快照 + PreconditionFailed + 作废后生成带差异的新单 | 保留（04 §5） | 全设计最值钱的一块：防“批 A 执行 B”与“批的事实已变” |
| ADR-05 | 回读核对（写进去≠写对了）；不一致即阻断 | 保留并强化（通道 A 必须回填后台实际值，不能只点“已核对”） | 没有读接口时，唯一的真值来源是人读到的后台实际值 |
| ADR-06 | 通道 A（执行清单）/ 通道 B（写接口），同一套动作清单与审批规则 | 保留；**把 A 定为第一天完整可用路径**，B 为适配器槽位 | DeepSeek 的 README 把“默认有写接口”当设计前提，与“尚无资格”的事实矛盾 |
| ADR-07 | 日本站相关缺项标“未知（TODO）”、不拿本土规则顶替、不编造 | 保留并产品化为 U-* 登记表 + “未知期间系统行为” | 把“未知”变成可执行的阻断行为，而不是散落的备注 |
| ADR-08 | 审计只追加、被拒绝的尝试也留痕、安全带清单、规则版本化 | 保留（04 §8、§12） | 取证与自证 |

## 2. 改（方向对、形态改）

| ADR | DeepSeek 版 | 改成 | 理由 |
|---|---|---|---|
| ADR-09 | 利润口径：到岸成本含佣金/退货损耗，利润再扣一次佣金/退货（专家评审实测的重复扣减）；漏达人佣金/支付手续费/汇率；文档算例自相矛盾（46.7% vs 55.7%） | 唯一口径（03 §3）：到岸成本只含 c1–c7；佣金/手续费/退货损耗单列且只扣一次；汇率、税口径入费率卡；**缺 BLOCKING 项 → 利润 UNKNOWN 且不进排序** | 口径不定，后面全是错的数上做对的机制 |
| ADR-10 | “不确定”双轨：动作路径 fail-closed，评分路径把 UNKNOWN 折算成风险扣分后仍可入榜 | UNKNOWN 分 BLOCKING / DEGRADING 两级；BLOCKING 进“数据缺口队列”，并告诉人“补哪项解锁几个候选”；DEGRADING 扣分上限 30 且需逐行展开 | 对“要不要花钱进货”和“要不要动手”应同样严格 |
| ADR-11 | 品类准入：风险品类作“风险扣分”，化妆品一路走到执行清单；示例主推化妆品，而跨境直邮下是否可售未核实 | **G0 白名单、默认拒绝**，在选品阶段即拦；上架清单再跑一次，命中则**整张清单不可执行** | 业务评审指出的 P0：做了也是白做；“不清楚就不做”（PR-3） |
| ADR-12 | 合规“忽略（填理由）”能放行 BLOCK 项 | BLOCK 没有忽略入口；只有“改后重检”或“上报法务（挂起）”；WARN 才需确认 | “拦截不是提醒”，否则出事时记录反而证明“已知风险仍放行” |
| ADR-13 | 单人模式靠“PM Agent 出机器复核签（第二签）” | **删除机器签**；单人运行显式标注，用延迟生效、查看门槛、周抽检、自批自执标记补偿；出现第二个自然人后自动启用制作者≠批准者 | 机器签违背 RL-2（Agent 无批准权），且把不可逆上架的一票交给 Agent（业务评审 P0） |
| ADR-14 | 风险处置 T0–T4 × 三种可逆性矩阵、四档 `risk_class`、DUAL_SIGN | **四种注册表处置**（AUTO / HUMAN_APPROVAL / HUMAN_INITIATED / NEVER）+ Gatekeeper 四种输出（ALLOW_AUTO / REQUIRE_HUMAN / BLOCK / HOLD）；矩阵保留为“开放新域时再引入” | P1 只有两个写动作且都是人批；多级矩阵是为不存在的动作写代码 |
| ADR-15 | 财务共签（AST-016 超成本闸门“需人批 + 财务共签”，本地零成本素材也要财务签） | 超预算放行由 **Owner** 批；不设财务角色 | 单人单店没有财务；“用几元的素材成本签字、却让定价错误自动执行”是倒挂（评审 P0-7）；定价由同意 2 + 价格地板价 BLOCK 约束 |
| ADR-16 | 多人审核阈值（≥3 家店/≥200 单/日待批>100）本期永远触发不了 | 以“是否出现第二个自然人”为触发，自动启用制作者≠批准者 | 阈值与现实脱节，导致永远停在单人模式的矛盾里 |
| ADR-17 | 上架执行卡里夹带改价/改库存 | **一卡一动作：新建商品**；初始价与初始库存是新建的必填字段；之后改价/库存只提醒“去后台” | 避免“批的是上架、执行的是上架+改价+改库存” |
| ADR-18 | 清单只有 6 个字段，运费脚注化，时效“可跳过” | 清单覆盖 9+ 必填字段；**送料与発送日数为阻断项**；“不承诺时效”改为需 Owner 签字承认风险（迟发会限流扣分） | 业务评审 P0：不填≠不考核 |
| ADR-19 | 只读“已连接/OAuth”与“API 未知”并存于各屏 | 统一：本期读通道“未建立”；所有平台读数显示“不可读/人工回填”，不显示 0 或正常 | 自相矛盾会让人误判店铺健康 |
| ADR-20 | 回读核对=点“我已核对” | 必须回填后台实际值；关键字段不一致即 `READBACK_MISMATCH` | 自证不是证据 |
| ADR-21 | 日文由中文操作者审批，无辅助 | 日文 + **中文回译** + 术语一致性标记；日语自然度由 LLM 只出 WARN | 操作者无法凭语感核对日文 |
| ADR-22 | 授权可含上架/素材类 | 本期**仅 ACT-SELECT 可授权**；同意 2 与上架永不可授权 | 对外发布内容的责任在人 |

## 3. 舍（不做或不带入）

| ADR | DeepSeek 版 | 舍弃 | 理由 |
|---|---|---|---|
| ADR-23 | 214 项功能全量清点（F 族 177 + 主线 37）、42/32/33/132/7/8 的多套计数并反复修订 | 舍；换成 38 项能力（02 §4）+ “不做=一条提醒 + 一个跳转”的统一形态 | 文档自己在多处计数不一致；清点本身不产生价值 |
| ADR-24 | 15 个 Agent（含 Order/Fulfillment/AfterSales/CS/Ads/Affiliate/Finance/Analytics…） | 舍；留 6 个（Pilot/Scout/Sourcer/Creator/Lister/Checker），合规与成本做成确定性服务 | PR-6：工作流优先；本期没有这些域的写动作，养 Agent 只产生噪音与 token |
| ADR-25 | 84 张表、RLS 租户隔离、店铺级 RLS 争论 | 舍；约 50 表（实际清点见 06），业务表带 `shop_id`，不做 RLS | 单租户单店；多租户是长期目标但不预付成本 |
| ADR-26 | S1–S27 “拿不准”信号、C1–C10 契约、D/G/F/B/C/H 评审编号体系 | 舍；`UNKNOWN`/`HOLD` 统一语义 + 05 的 C-1…C-10 + INV/AC | 编号体系只对追溯有用，实现者需要的是可测试的规则 |
| ADR-27 | Phase 2：32 项只读预警（依赖读接口） | 舍；P1 内只做“每周体检录入 + 盲区声明 + 去后台处理提醒”，自动读取留 P2 | 读接口未知；不能为了凑功能项暗示健康 |
| ADR-28 | 跨店批量下发的整套 UI 与机制（09 册、画面 12） | 舍（仅留 `shop_id`）；P3 再设计 | 本期一家店；“按多店可复制设计”落成“表带 shop_id”这一个动作即可 |
| ADR-29 | 13 个原型页 + 14 个“Phase 2/不做”画面的完整设计 | 舍；10 屏 | 一条链做透 |
| ADR-30 | 审批 TTL 的新旧口径并存（“HUMAN 24h 到期作废”一处残留） | 舍；统一“不过期，只催办”，INV-2 用快进时钟测试 | 红线一 |
| ADR-31 | 保证金“可调阈值只能调小” | 舍；保证金实额只读展示，预警线另设，且不当硬闸门 | 金额是平台定的，不是配额 |
| ADR-32 | 12 本设计册 + 7 本调研底稿 + 3 份历史快照（约 1.5MB 文本） | 舍；一套 12 个文件的 AI 设计书；调研底稿仅作来源引用 | 阅读与实现成本；多处自相矛盾 |

## 4. 新增（Claude 版补充）

| ADR | 新增 | 理由 |
|---|---|---|
| ADR-33 | 开工前置清单 Readiness（6 项）与首次引导 | 把散落各处的“未知即阻断”变成一个可操作入口 |
| ADR-34 | `required_viewed` 查看门槛 + 人时账本 | 把“人真的看过”“人一天的出手次数可数”变成可测指标，而不是文案 |
| ADR-35 | 工作流优先立场（PR-6）与 Tool Gate 静态约束 | 保证红线由结构而非约定实现 |
| ADR-36 | 数据缺口队列（CAP-CAN-06） | 在“未知很多”的现实下仍给人可做的下一步 |
| ADR-37 | 每周体检录入 + 盲区声明；上架结果回填 + 权重校准建议 | 补上专家指出的“出货端/反馈端”缺口，同时不假装有读接口 |
| ADR-38 | 视觉模型截图识别导入 + 强制人工确认 | 零接口下的进料头（`source_grade=C`，未确认不进评分） |
| ADR-39 | 动作注册表的 `HUMAN_INITIATED` 处置 | 区分“人点击即决定”（导入、保存方向、导出）与“需要审批单”的动作，避免为每个点击造审批单 |

## 5. 效率与自动化补充（2026-10-21）

| ADR | 决策 | 理由 |
|---|---|---|
| ADR-40 | 上架通道增加 **A2 批量上架包**（官方模板 + 素材包一次上传，导出文件自动读回），推荐为 P1 主通道；B（写接口）/C（授权 ERP）并行申请 | 逐项照做每品约 19 分钟；批量后约 2.8 分钟；仍是人手上传，不违反 NV-5 |
| ADR-41 | **不做** RPA/浏览器自动化操作卖家后台 | 违反 NV-5 与平台条款，封店风险，页面一改即失效 |
| ADR-42 | 数据采集统一为**连接器框架**：只读、白名单、观测表、校验、新鲜度、来源分级、可回退、可关停 | “能自动的全自动”，同时不放弃“规则判定”“未知即停” |
| ADR-43 | 汇率改为**自动获取**（欧洲央行参考汇率交叉算 JPY/CNY，备源为中间价文件），突变待人确认 | 汇率每天用，手填既慢又会过期 |
| ADR-44 | 读回改为**上传商品导出文件自动比对**，卖家 SKU 带载荷哈希前 8 位作关联键 | 取消逐字段手填；对账有据 |

## 6. 业务对比补强（2026-10-22，借鉴 DeepSeek 版）

> 与 DeepSeek 版逐项对照后，本版**多数业务维度更严**（16 项成本、`tax_regime` 单枚举、G0 白名单 + 旗标、ASSUMED_WORST、回读必须回填实际值）。只有两处 DeepSeek 版做得更细，吸收进来：

| ADR | 补强 | 理由 |
|---|---|---|
| ADR-45 | 新增 03 §5.3.1「旗标 × 日本法令」对照表：電波法（技適）・UN38.3／IATA・電気用品安全法・医薬品医療機器等法・食品衛生法・酒税法・商標法，逐条写「需要的资质 / 主体要求 / 未核实」 | 原设计只有 `has_radio`／`has_battery` 这类旗标名，实现者不知道要哪张证，容易把「未核实」当成「可以做」 |
| ADR-46 | 新增 04 §5.5「挂起 / 终止 / 重跑」三条不变量：挂起不自动重试；终止不回滚已完成部分并生成去后台清单；补输入要重跑预检 | 少了这三条，实现会把「重试」当万能钥匙，或在终止批次时以为已经撤回了 |
