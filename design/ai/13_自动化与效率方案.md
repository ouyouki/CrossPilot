# 13 · 自动化与效率方案（上架与数据采集）

> 起因：按 12 号手顺估算，5 个品/天人要用约 3.7 小时，其中后台手工上架占 34%，货源/预采录入占 41%，汇率等数据靠手填。本册给出**最高效的方案**，并把“能自动采集的数据一律自动采集”做成设计。
> 约束不变：NV-5（不爬取、不模拟登录、不绕过验证码、不做 RPA 操作卖家后台）；一切自动采集只用**官方接口、已授权的数据服务、公开的官方数据文件**。审批、红线、哈希与前置条件机制不变。

## 2. 上架：三条通道，推荐“先批量、并行开 API”

| 通道 | 做法 | 人每品用时 | 前提 | 红线与审计 |
|---|---|---|---|---|
| **A1 逐项照做**（旧） | 复制字段，在后台逐个新建 | 约 19′（15′ 上架 + 4′ 回填） | 无 | 无 |
| **A2 批量上架包（推荐，立即可做）** | 系统把当天已批准的 N 个品生成**官方模板文件 + 素材包**；人在卖家后台**一次上传**；后台的失败文件回传系统自动解析；上架后人导出一份“商品导出文件”丢回系统，**系统自动读回比对** | 约 2.8′（一批 5 个：上传与处理 ≈12′ + 导入导出 ≈2′ → 14′ ÷ 5） | 模板对日本站跨境店可用（U-21）；图片传输方式（U-22） | 仍是人手上传（不是 RPA）；每个品仍须各自的同意 2；批次只是“执行打包” |
| **B 写接口直传（终局）** | 经 Product API 建品、上传媒体，自动读回；24h 内可一键下架 | 0′ | U-1/U-2 答复；或经授权 ERP/服务商通道（U-20） | ACT-LIST-CREATE 不变；适配器 `PlatformWriter` 换实现 |
| **C 授权 ERP/服务商通道** | 在应用市场授权服务商，由其 API 完成建品；本系统生成其导入格式或经其开放接口推送 | 约 1′（仅在服务商后台确认） | 服务商费用与条款；其对日本站跨境店的支持（U-20） | 数据经第三方；需把服务商列入出站白名单与审计 |
| ✗ **浏览器自动化/RPA 操作卖家后台** | — | — | — | **不做**：违反 NV-5 与平台条款，封店风险，页面一改即失效 |

**推荐路径**：**A2 立即上线** → 并行启动 B（申请 Custom App；若跨境店不能注册，则走 C）→ B 通后 A2 降为故障兜底。三条通道**共用同一份载荷、同一套审批与读回口径**，切换只换“最后一下谁完成”。

### 2.1 A2 批量上架包的设计

1. **打包**：同意 2 通过且前置条件成立的商品，进入“上架批次”（`listing_batches`）。批次按**末级类目**分组（一个模板一个类目，官方限制）。
2. **模板生成**：首次对每个末级类目，人把官方模板上传一次（`template_files`，记版本号/列定义）；之后系统按模板列映射填充载荷（一行一个 SKU）。模板版本变化或列不匹配 → **阻断生成**（G4），不猜。
3. **关联键**：卖家 SKU 填 `CP-<候选编号>-<载荷哈希前 8 位>`。读回时凭它把后台行与批准载荷一一对应；人在后台改了内容，哈希对不上即 `READBACK_MISMATCH`。
4. **媒体**：按 U-22 二选一——(a) **图片空间模式**：系统导出按 SKU 命名的素材包，人一次性拖入图片空间；(b) **URL 模式**：系统通过“媒体网关”提供**限时、不可猜的公网链接**（默认 48 小时，只含该批次已批准素材，批次结束即失效，访问记审计）。
5. **失败回收**：后台返回的失败文件上传回系统，**自动解析“失败原因”并映射到载荷字段**（如缺必填属性、类目不符），给出修正建议；修正后重新生成、再上传。**修正若改变对外内容，按 INV-14 作废并重走同意 2**。
6. **自动读回**：人从卖家后台导出商品列表（标题、价格、库存、类目、状态等）上传，系统逐项比对关键字段（标题、价格、送料、発送日数、类目、原産国、返品条件、图片数、**审核状态**），一致 → `SUBMITTED/LIVE`；不一致 → `READBACK_MISMATCH`。**不再让人逐字段回填**。
7. **限额与保护**：每批 ≤ `batch_max`（缺省 20）；每批总次数受每日清单上限约束；**批量上传失败不自动重试**，必须人确认。
8. **仍然不变**：每个品一张同意 2 审批单（一品一单）；批次不是批量批准；清单与素材包在批准前不可下载。

### 2.2 B/C 的预留
`PlatformWriter` 接口不变；新增 `ApiWriter`（B）与 `ErpWriter`（C）。B/C 下“批次”仍存在（只是 `channel` 不同），读回改为自动拉取；A2 保留为兜底。

## 3. 数据自动采集：连接器框架

### 3.1 原则（与红线对齐）

1. **只用合法来源**：官方 API、已授权的数据服务（有合同/令牌）、公开的官方数据文件。**不抓取**平台、货源站或竞品页面（NV-5）。
2. **经 Tool Gate**：所有出站读取都是 `ACT-FETCH-DATA`（AUTO，外部只读，域名白名单，审计）；结果先进**观测表**（只追加），通过校验后才被业务使用。
3. **确定性校验**：格式、范围、突变检测（如汇率日变化 >3% → 暂存并 HOLD 等人确认，不自动采信）；校验由规则完成，不用大模型。
4. **新鲜度 SLA**：每类数据声明 `max_age`；超期 → `STALE` → 依赖它的动作 `HOLD`（沿用 PC-FX-FRESH / PC-SOURCE-FRESH）。**失败也不静默**：连续失败 3 次告警并收紧。
5. **来源分级与回退**：每条观测带 `source_grade`（A 官方接口/文件，B 授权第三方，C 手录）、`source_id`、`fetched_at`、原始响应哈希；主源失败 → 备源 → 人工录入（降为 B/C，并写原因）。
6. **只读、最小权限**：令牌放密钥库，不入库不入日志；连接器没有任何写外部的能力。
7. **每个连接器一个开关**（`capability_flags`），可降为“只出建议”或关闭；往松切走 24 小时规则。

### 3.2 自动采集清单

| 数据 | 现在 | 自动方案 | 频率 | 失败时 | 阶段 |
|---|---|---|---|---|---|
| **汇率 CNY→JPY** | 手填 | **自动**：欧洲央行每日参考汇率（经公开接口取 EUR/CNY 与 EUR/JPY，交叉算出 JPY/CNY），备源为中国外汇交易中心 CNY/JPY 中间价文件；存 `fx_rates`（来源、参考日、取数时间、原始哈希） | 每个工作日 09:00 JST，另 15:00 补取 | 超 24 小时 → `STALE` → 在途审批 HOLD；突变 >3% → 待人确认 | P1 |
| **日本关税率 / HS** | 手填 | 日本海关官方税率表（公开文件）**定期导入**，按 HS 分类查税率；税制变更公告提醒 | 季度 + 事件 | 无新文件不影响，仅提示核对 | P1（半自动：系统取文件并解析，人确认一次） |
| **消费税率、日本节假日** | 配置 | 内阁府公布的节假日 CSV 自动年更；税率为带生效日的配置 | 年度 | 保留上一版，到期前 30 天提醒 | P1 |
| **榜单 / 竞品 / 价格带** | 人导出 CSV | **已授权的数据服务**（若购买了带 API 或定时导出的分析服务）按计划拉取；或把其定时导出文件放进约定文件夹自动入库 | 每日夜间 | 当日无数据 → 候选数据标 DEGRADING，不静默 | P1.5（P1 保留手工 CSV） |
| **货源价 / 重量 / 起订** | 人贴链接填字段 | **已授权的采集工具**（如 ERP 的采集箱）导出文件自动入库，系统解析为预采数据；1688 官方开放接口（需企业资质）为 P2 | 事件（选中即同步） | 缺字段 → 明说缺什么 | P1（导出文件）/ P2（接口） |
| **国际运费报价** | 手填 | 货代报价表按模板**一次导入**，带有效期与版本；货代开放接口为后续选项 | 报价变更时 | 过期 → c3 缺失 | P1 |
| **平台佣金 / 手续费 / 规则** | 手填 | 无官方接口；对**公开的费率/规则页面**做每日**变更检测**（只比对页面内容是否变化，不解析入库），变化即提醒人核对并更新 | 每日 | — | P1（需法务确认公开页面检测可接受） |
| **上架结果 / 审核状态** | 人回填 | A2：导出文件导入；B：接口读取 | 每批 / 每日 | — | P1 / P1.5 |
| **店铺体检（违规分、迟发率…）** | 每周手录 | 后台导出的店铺数据报表导入；B/P2：接口读取 | 每周 | 超 8 天未更新 → 盲区提示 | P1 / P2 |
| **订单 / 结算 / 实际毛利** | CSV 回填 | 结算报表导出导入；接口读取 | 每周 | — | P1 / P2 |
| 素材成本 / 模型花费 | 自动 | 已自动（调用台账） | 实时 | — | P1 |

### 3.3 汇率的具体做法（示例）
`JPY/CNY = (EUR→JPY) ÷ (EUR→CNY)`，取同一参考日；写入 `fx_rates`：`pair='CNYJPY'`、`rate`、`ref_date`、`source_id`、`fetched_at`、`raw_hash`。审批与成本快照引用 `fx_rate_id`（INV-16）。**人不再录汇率**；人工覆盖仅在主备源都失败时允许，降为 `source_grade=C` 并写原因。

## 4. 效率对比（5 个品/天，设计估算，需实测）

| 环节（人每品，分钟） | 旧 | 新（P1：A2 + 连接器） | 终局（B + 授权采集） |
|---|---|---|---|
| 榜单/数据导入（每天） | 5′/天 | 0（自动同步）～5′/天（手工兜底） | 0 |
| 预采 | 8′ | 3′（预采数据自动带入，人确认） | 2′ |
| 同意 1 | 1′ | 1′ | 1′（或授权代批） |
| 确认采 | 10′ | 4′（授权证据与属性仍需人） | 4′ |
| 素材预览/退回 | 2′ | 2′ | 2′ |
| 同意 2 | 4′ | 4′ | 4′ |
| 后台上架 | 15′ | **2.4′**（一批 12′ ÷ 5） | 0′ |
| 回填/读回 | 4′ | **0.4′**（一批 2′ ÷ 5） | 0′ |
| **合计 / 品** | **44′** | **≈16.8′** | **≈13′** |
| **5 品/天** | **≈3.7 小时** | **≈1.4 小时** | **≈1.1 小时** |

结论：人的时间由 3.7 小时降到约 1.4 小时（P1），其中**决策仍约 25 分钟**；剩下的主要是授权证据与属性确认（这些是责任所在，不能自动）。
