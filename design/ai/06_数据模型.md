# 06 · 数据模型

> PostgreSQL 16。约定：主键 `id uuid`（`uuidv7` 优先）；时间 `timestamptz`；金额 `numeric(18,4)` + `currency char(3)`（JPY 实际取整）；枚举用 Postgres `ENUM` 或带 `CHECK` 的 `text`；所有业务表有 `shop_id`（+ `created_at`、`updated_at`），除非另注。**不用 `float` 存金额**（INV-16）。迁移用 Alembic。
> 这里只写**关键列与约束**；实现者补齐索引与审计字段。

## 7. 关键约束 DDL 片段（PostgreSQL 可执行写法）

> PostgreSQL 的 `CHECK` 不能含子查询，外键不能指向视图——下面是可行写法。

```sql
-- 审批人必须是自然人（INV-4）：复合外键 + CHECK，不用子查询
ALTER TABLE users ADD CONSTRAINT users_id_kind_uq UNIQUE (id, kind);
ALTER TABLE approvals
  ADD COLUMN approver_kind text DEFAULT 'human',
  ADD CONSTRAINT approver_is_human CHECK (approver_kind = 'human'),
  ADD CONSTRAINT approver_fk FOREIGN KEY (approver_user_id, approver_kind) REFERENCES users (id, kind),
  ADD CONSTRAINT approver_xor_grant CHECK (status IN ('DRAFT','PENDING')
        OR ((approver_user_id IS NULL) <> (delegated_via_grant_id IS NULL)));

-- 审批状态转换表（无时间边）（INV-2）：触发器查表
CREATE TABLE approval_transitions(from_status text, to_status text, PRIMARY KEY(from_status,to_status));
-- BEFORE UPDATE OF status 触发器：(OLD.status,NEW.status) 必须在表内；PENDING 后内容列不可更新

-- 利润为空当且仅当存在 BLOCKING 缺失（INV-10）：用 jsonb_path_exists，items 每项带 severity
ALTER TABLE cost_snapshots ADD CONSTRAINT profit_unknown_iff_missing
  CHECK ((profit IS NULL) =
         jsonb_path_exists(items, '$.* ? (@.status == "MISSING" && @.severity == "BLOCKING")'));

-- 授权：只可授权 ACT-SELECT；用量不超；24h 后生效；有效期 ≤30 天（INV-5/6/21）
ALTER TABLE grants
  ADD CONSTRAINT grantable_only CHECK (action_type = 'ACT-SELECT'),
  ADD CONSTRAINT uses_cap CHECK (used_count <= max_uses),
  ADD CONSTRAINT expiry_cap CHECK (expires_at <= created_at + interval '30 days');
-- 原子消费：UPDATE grants SET used_count = used_count + 1 WHERE id=$1 AND status='ACTIVE'
--   AND effective_from <= now() AND expires_at > now() AND used_count < max_uses RETURNING *;

-- 图片 ≤9 张：槽位约束代替触发器计数
ALTER TABLE asset_items ADD CONSTRAINT slot_range CHECK (slot BETWEEN 1 AND 9);
CREATE UNIQUE INDEX one_image_per_slot ON asset_items (asset_set_id, slot) WHERE type = 'IMAGE';

-- 未结单唯一（防重复提案、防双击重复批）
CREATE UNIQUE INDEX one_open_approval ON approvals (shop_id, action_type, subject_key)
  WHERE status IN ('DRAFT','PENDING','APPROVED','EXECUTING');

-- 审计只追加（INV-11）：迁移角色当 owner，应用角色另建
REVOKE ALL ON audit_log FROM app_role;  GRANT INSERT, SELECT ON audit_log TO app_role;
```

## 8. 枚举速查

- 候选/商品状态：见 03 §1.2。
- 审批状态：`DRAFT, PENDING, APPROVED, EXECUTING, EXECUTED, EXEC_FAILED, REJECTED, RETURNED, SUPERSEDED, VOID`。
- 处置：`ALLOW_AUTO, REQUIRE_HUMAN, BLOCK, HOLD`；注册表处置：`AUTO, HUMAN_APPROVAL, HUMAN_INITIATED, NEVER`。
- `license_type` / AIGC 等级：见 03 §4.2、§5.2。
- 回读结果：`MATCH, MISMATCH_CRITICAL, MISMATCH_NONCRITICAL`；关键字段：标题、价格、送料、発送日数、图片数。
