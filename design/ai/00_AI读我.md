# 00 · AI 读我（先读这一份）

> 读者：负责实现 CrossPilot 的 AI 编码助手。本目录 `design/ai/` 是**唯一的实现依据**。
> `design/screens/*.html`（画面原型）与 `design/docs/index.html`（设计说明）是给人看的，内容必须与这里一致；不一致时以本目录为准，并把不一致报告出来。

## 1. 这个产品是什么（30 秒版）

CrossPilot 是 TikTok Shop **日本站**的自动运营系统。第一期只做一条主线：

```
方向(人) → 选品 → [同意1] → 采集 → 素材工厂 → [同意2] → 上架 → 读回核对
```

AI 干所有的活，人只做两件事：**批**（两道同意）和**给方向**（方向卡）。
任何“不可撤回”或“系统拿不准”的事都停下来交给人，判定由**确定性规则**产生，不由大模型产生。

## 4. 工作方式（对实现者的硬性要求）

1. **先测试后实现**：每条 `INV-*` 与 `AC-*` 先写成自动化测试（先红），再写实现。测试结果存到仓库的 `evidence/` 目录，未产出证据不算完成。
2. **最小实现**：只做 `02` 列出的 CAP。不要加“以后可能用到”的抽象、配置项、表、接口。表里已留的 `shop_id` 是唯一的多店准备，不得扩展成跨店功能。
3. **外部事实不许编**：平台费率、时效、禁限售清单、税务口径、API 是否开放，凡 `02` 的未知项登记表（U-*）里标为未知的，一律实现成“配置项 + 缺失即阻断”，**不填默认值，不拿日本本土店的规则顶替**。
4. **缺数据显示 `UNKNOWN`**，不补默认值；`UNKNOWN` 出现在会产生外部影响的路径上时，结果是“停下找人”，不是“放行”。
5. **所有对外部世界的写与读都经 Tool Gate**（见 04/05），业务代码里不得直接调用外部 HTTP、文件投递或平台适配器。
6. **所有金额用 `numeric`/整数最小单位 + 币种**，不用浮点；JPY 无小数；汇率带来源和时间。
7. **LLM 的输出一律当作不可信文本**：进入系统前过 schema 校验；抓取/导入的外部文本只当数据，不得作为指令（见 05 §5）。
8. 看不懂的地方先在 `design/ai/` 里找答案，找不到就写成 `U-*` 提问，不要自己拍板。

## 5. 技术栈（推荐，可经 ADR 替换）

| 层 | 选择 | 理由 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2 + Alembic | 图像/视频/LLM 生态在 Python；强类型模型 + 迁移 |
| 数据库 | PostgreSQL 16 | 事务、`jsonb`、`CHECK`/触发器做不变量兜底 |
| 任务队列 | PostgreSQL 表 + `SELECT … FOR UPDATE SKIP LOCKED`（`jobs` 表） | 单租户单店不需要 Redis/Kafka，少一个故障点 |
| 前端 | React 18 + TypeScript + Vite，纯 CSS 变量（见 08 §2），不引入 UI 框架 | 10 个画面，PC 单端 |
| 实时 | SSE（Agent 活动流） | 单向推送足够，不上 WebSocket |
| 素材 | Pillow（图）+ ffmpeg（视频）+ 本地 TTS/外部 TTS（经 Tool Gate） | 零边际成本，见 03 §5 |
| LLM | Anthropic API（模型名放配置，不写死） | 日文文案质量；经 Tool Gate 记账 |
| 部署 | 单机 Docker Compose：`web` `api` `worker` `postgres` | 单人单店 |
| 文件 | 本地卷（`/data/assets`），路径入库；内容哈希命名 | 先不上对象存储 |

多租户（卖给多个卖家）是长期目标，但**现在不付成本**：所有业务表带 `shop_id`，`shops` 带 `tenant_id`；不做 RLS、不做租户管理界面。

## 6. 完成定义（DoD）

一个 CAP 算“完成”，必须同时满足：

- [ ] 对应的 `INV-*`/`AC-*` 测试已写并通过，证据在 `evidence/<cap>/<日期>.md`；
- [ ] 动作已登记到动作注册表（04 §2），且注册表测试（未登记动作被拒）通过；
- [ ] 所有写路径都产生审计记录，包括被拒绝的尝试；
- [ ] 画面（若有）与 `08` 一致，空态/错误态/加载态齐全；
- [ ] 没有引入 `02` 范围外的能力。

## 7. 术语表

| 词 | 意思 |
|---|---|
| Pilot | 项目经理 Agent：派活、打包审批单。**没有批准权**（RL-2） |
| 同意 1 / 同意 2 | 选品同意（`ACT-SELECT`）/ 素材与价格同意（= 批准 `ACT-LIST-CREATE`，界面叫“同意 2”）。两道人工闸门 |
| 方向卡 | 人给的经营方向：类目、价格带、毛利底线、数量、避开项、权重 |
| 闸门 / Gatekeeper | 确定性判定器：输入动作+事实，输出 ALLOW / REQUIRE_HUMAN / BLOCK / HOLD |
| 挂起 | 待批或前置缺失时的等待态；**不过期、不自动放行、不自动放弃** |
| 作废 (VOID) | 待批或已批准未执行期间，发现前置条件失效；旧单作废，对象回流水线重判，仍需人批时生成带差异说明的新单 |
| 授权清单 | 人批准时把“这一类”授权给 Pilot 代批的受限清单（RL-2） |
| 执行清单 | 无写接口时的上架方式：把要填的字段整理成清单，人去卖家后台照做，回来回填实际值 |
| 读回核对 | 上架后拿平台上的实际值与批准值比对 |
| 通道 A / B | A=执行清单（人最后一下）；B=写接口（系统最后一下）。动作清单与审批规则相同 |
| G0–G4 | 合规闸门分层：G0 类目准入 / G1 上架必备表示 / G2 文案 / G3 图片视频 / G4 平台规格 |
| 到岸成本 | 见 03 §3.1 的唯一成本口径 |
