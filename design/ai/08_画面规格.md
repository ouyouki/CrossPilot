# 08 · 画面规格

> 对应的可点击原型在 `design/screens/*.html`（演示数据，纯静态）。本册是**实现规格**：区域、字段、状态、文案、交互。原型与本册不一致时以本册为准。
> 设备：Windows PC 浏览器（Chrome/Edge），基准 ≥1366×768；手机可打开但不专门优化（D1）。

## 1. 设计目标与取舍

1. **让人的每一次点击都真的看过东西**（01 PR-1）：审批界面第一屏就给出“批什么、依据是什么、最坏会怎样”。
2. **让人一眼看出哪里在等自己**：全站只有一种“等你”的颜色（琥珀）；被拦的只有一种颜色（红）。
3. **极少文字**：每屏解释性文字 ≤ 可见正文的 12%；教程与原理不进画面（进操作手册/设计说明）。
4. **没有的功能就没有入口**：不做的域只有“一条提醒 + 一个跳转”。
5. **缺数据说缺数据**：绝不用 0、“正常”、绿色去暗示健康。

## 2. 设计语言

### 2.1 颜色语义（一个颜色一个意思）

| Token | 含义（固定） | 用在哪 |
|---|---|---|
| `--primary` | 可点击 / 选中 / 当前步骤 | 主按钮、选中行、当前导航 |
| `--wait` 琥珀 | **等你决定 / 挂起 / 数据待补** | 待批徽标、挂起标签、NEEDS_DATA |
| `--block` 红 | **被拦、不可做、不一致** | G0 不可售、BLOCK 命中、READBACK_MISMATCH |
| `--ok` 绿 | **已通过且已核对** | 合规通过、读回一致、LIVE |
| `--info` 蓝灰 | AI 正在做 / 自动完成 | Agent 活动流、进行中 |
| 中性灰 | 结构与正文 | — |

浅/深色主题都要自动正确（`color-scheme: light dark` + `light-dark()`）；正文对比度 ≥ 4.5:1。**不用单边彩色边线**装饰；强调靠整块浅底 + 文字色。

### 2.2 字体与数字

- 中文界面文字：`"Noto Sans SC","Microsoft YaHei UI",system-ui`；日文内容容器加 `lang="ja"`，用 `"Noto Sans JP","Yu Gothic UI",Meiryo`；
- 字号（v2，已加大）：正文 16、表格 15、辅助 14、徽标 13、标题 20–26；PC 基准下不再使用 <13px 的文字；字重只用 400 与 600；数字 `font-variant-numeric: tabular-nums`；
- 间距只用 8 / 12 / 24；圆角 4 / 6 / 10；按钮高 30（大 38 用于决定区，小 26 用于行内）；图标内联 SVG，不用 emoji。

### 2.3 应用壳（v2：明亮侧栏，宽 244px；右详情 392px）

```
┌ 顶栏 52px：面包屑 · 店铺名（单店，不可切）· [单人运行] 标签 · 通知 · 身份 ┐
├ 左导航 208px ─┬ 主区（自适应）──────────────────────┬ 右详情 340px（选中项）┤
│ 今日          │ 页首一句话 + 主按钮                  │ 证据 · 影响面 · 版本  │
│ 流水线        │ 指标条（≤4 张）                      │                       │
│  方向 选品    │ 主体（列表卡/流程卡）                │                       │
│  货源 素材 上架│ 活动流                              │                       │
│ 治理          │                                      │                       │
│  待批(徽标)   │                                      │                       │
│  授权 审计    │                                      │                       │
│ 设置          │                                      │                       │
└───────────────┴──────────────────────────────────────┴───────────────────────┘
```

- 导航只在左侧；顶部不放页签；高风险信息（风险、阻断原因、不可逆）不折叠；
- 窄屏：821–1080px 仍保持三栏（左 180/右 300）；≤820px 才折右栏到下方并收左导航；表格先减列，不缩字；
- 页首右上角一个“?”，点开对应操作手册小节，无副作用；
- 每屏**一个主按钮**，位置固定在页首右侧。

### 2.4 通用状态

| 状态 | 规格 |
|---|---|
| 空态 | 一句话 + 一个按钮（“还没有候选 → 去导入榜单数据”）；**空态不暗示正常**（体检未录入 ≠ 一切正常） |
| 加载态 | 骨架屏；超过 3 秒显示“仍在加载”，不转圈无限 |
| 错误态 | 红色提示条：发生了什么 + 下一步按钮；`problem+json` 的 `next_action` 直接渲染成按钮 |
| 挂起 | 琥珀标签“等待 · 已挂起 X 小时 · 不会自动放行或放弃”；不显示倒计时 |
| 离线/断流 | 顶栏小红点“实时更新已断开，点此重连”；页面数据标注“截至 hh:mm” |

### 2.5 文案纪律

- 界面**不出现**：哈希、内部字段名、`ACT-*`/`RULE-*` 编号（审批单“详情”折叠区与审计页除外）、阶段口径（Phase/本期）、机制解释；
- 红线固定文案（不得改写）：

| 位置 | 文案 |
|---|---|
| 审批决定区上方 | 未批准绝不执行；未决期间挂起等待，不自动放行也不自动放弃。 |
| 审批单角色说明 | Agent 默认无批准权，不能批自己提的单。 |
| 授权清单页头 | 授权范围只能收窄，不能放宽；任何放宽都要回到人，并在 24 小时后生效。 |
| 不可授权动作 | 这类动作必须由你本人批准，不能交给 Pilot。 |
| 参数失效 | 批准时依据的事实已变化，原批准作废，不会执行；已生成新单，附差异说明。 |
| 单人运行 | 单人运行：没有第二位审批人，系统用延迟生效、抽检和查看门槛补偿。 |
| 通道 A 提醒 | 本期无写接口：请在卖家后台照清单操作，并回填后台实际值；平台侧是否写入以卖家后台为准。 |
| 体检空态 | 本期不自动读取履约指标（迟发率、取消率等），这是盲区；请每周在后台查看并录入。 |

## 2.6 换肤与字体（v2）

- **换肤**：`<html data-skin="mint|sky|violet|paper|navy|carbon">`，6 套（明亮·青 默认 / 天空·蓝 / 薰衣草·紫 / 纸白·靛蓝 / 深蓝·橙 / 碳黑·青）。皮肤只改框架色（侧栏、品牌、主色、英雄区深色面板）；**语义色（琥珀/红/绿/蓝灰）与图表系列色不随皮肤变化**。顶栏“换肤”按钮或 Alt+1–6 切换，记在 localStorage（兜底 window.name 与 `?skin=`）。
- **字体（中日文，Windows 简体中文与日文环境）**：拉丁 IBM Plex Sans → Segoe UI；中文 Microsoft YaHei UI → YaHei → Noto Sans SC；日文 Yu Gothic UI → Yu Gothic → Meiryo UI → Meiryo → Noto Sans JP。页面 `lang="zh-CN"`，**含假名的元素自动标 `lang="ja"`**，使同形异体字（直、骨、返、角）按语言取正确字形；`font-synthesis:none`，字重只用 400/600。
- **手机商品页示意**按 TikTok Shop 日本站 App 商品详情页版式绘制（`phone.js`）：顶部标签、图片页码、税込价格、タイトル、レビュー、配送/返品/原産国、ストア卡、商品詳細、特定商取引法に基づく表記、底部「カートに追加／今すぐ購入」。实际渲染以卖家后台预览为准。

## 4. 逐画面规格

### SCR-01 今日

| 区域 | 内容 |
|---|---|
| 页首 | “今天有 5 件事等你，预计 25 分钟” + 主按钮“去处理第一件” |
| 就绪条 | 开工前置清单 6/6（未全绿时置顶，列缺项并直达设置；流水线暂停并说明） |
| 指标条（4） | 待批 · 在制品（选品/采集/素材/待上架各几个）· 今日已自动完成 · 挂起 |
| 流水线进度 | 一条横向进度：候选 24 → 已选 5 → 采集 4 → 素材 3 → 待批 3 → 上架 2 → LIVE 1，点击进入对应画面 |
| 等你拍板（≤5 行） | 审批单标题、类型徽标、挂起时长；按服务端优先级排序；**高风险不折叠** |
| 去后台处理 | 提醒行（一条提醒 + 外链）：如“2 个已上架商品在后台的价格低于你的毛利底线”“保证金预警线” |
| 本周体检 | 未录入 → 琥珀卡“本周体检未录入（盲区）”+ 按钮；已录入显示 5 个值与阈值状态 |
| 人时账本 | 今日用时、日均出手次数、积压批准占比（>阈值变琥珀） |
| Agent 活动流 | 6 条最近动作（来自审计只读视图），含被拒绝的尝试；点击进审计详情 |

状态：流水线暂停（就绪未全）→ 主区顶部红/琥珀条；Agent `SUGGEST_ONLY` → 活动行标“仅建议”。

### SCR-02 方向

- 表单分三段：**做什么**（类目多选，仅限白名单；价格带；避开关键词/品牌）、**要多少**（每日候选上限、同意 1 单批上限、毛利底线*必填*、毛利目标）、**怎么排**（四权重滑块，和为 100，显示默认值与当前值；运费占比警告线）。
- 右栏：历史版本与差异；放宽项（降底线/加类目）显示“已放宽”徽标。
- 保存即生效（版本化）。必填缺失 → 保存按钮禁用并指出字段。
- 页脚固定一行：“没有方向，系统不会选品。”

### SCR-03 选品

| 区域 | 内容 |
|---|---|
| 页首 | 日期 + 导入入口“导入榜单数据”（CSV/粘贴/截图）+ 主按钮“发起同意 1（已勾 N/10）” |
| 泳道切换 | 可选 12 · 数据待补 7 · 不可售 5（三个 Tab，数字即数量） |
| 可选表 | 勾选、品名（日文）+ 中文名、类目、售价（税込）、**毛利 %**、需求信号（来源徽标 A/B/C）、竞争、分数、**一句话理由**、风险旗；行点击打开右栏 |
| 右栏 | 成本分项表（每项 值/来源/日期/状态）、需求与竞争信号、打分分解、G0 记录、方向版本 |
| 数据待补 | 每行显示“缺 c3 国际运费”并有“去补”链接；顶部显示“补 X 可解锁 3 个候选”；**不显示分数** |
| 不可售 | 行置灰、不可勾选、写明命中（“类目未登记/含无线/化粧品…”）；**没有“强行选”按钮** |
| 批量勾选约束 | 超过 `selection_cap` 禁用；含“数据不全”标记的行勾选时强制展开确认 |

“发起同意 1”只生成审批单（进 SCR-06），本屏不直接批。

### SCR-04 货源

- 左：采集箱列表（状态：待录入/待确认/已确认/重复）；右主区：货源表单（链接*必填*、标题、规格、价格、阶梯价、起订、重量体积、发货地、品牌授权）。
- 图片区：每张图必选 `license_type` 并上传证据；`none` 显示红标“仅内部比对，不会进入素材生成”。
- 属性旗标三项必勾（有电池 / 有无线 / 与食品接触）；货源确认清单五项（有货、起订、发货时效、授权、质量风险自检）。
- 品牌/IP 初筛命中显示“需人工确认”。缺字段 → 明说“请补：重量、起订量”，不猜。
- 主按钮“保存并确认货源”：全部满足 → 状态 SOURCED，素材流水线自动启动。

### SCR-05 素材

| 区域 | 内容 |
|---|---|
| 左 | 商品列表 + 状态（生成中 / 检查未过 / 已检查 / 待同意 2 / 已批准） |
| 主 | 分区：标题/卖点/介绍页（**日文原文 + 中文回译 + 术语标记**并排）、图片 9 宫格（每张可打开**依据图并排** + 授权证据 + AIGC 等级）、视频播放器（含“AI生成”标注检查）、**合规报告** |
| 合规报告 | 按 G1–G4 分组；BLOCK 红色置顶：命中片段、规则、改法；**没有“忽略”**；WARN 琥珀：待在同意 2 逐条确认 |
| 操作 | 退回/重生成（预定义原因必选，自由文本选填）；人工改文案会生成新版本并重检；主按钮“送审同意 2”（仅当无 BLOCK） |
| 价格卡 | 建议价、毛利、成本分项折叠区；售价低于地板价显示红色并禁用送审 |

### SCR-06 待批

| 区域 | 内容 |
|---|---|
| 左 | 队列（服务端优先级）：筛选（同意 1 / 同意 2 / 例外 / 挂起）；每行：标题、类型徽标、挂起时长 |
| 主（审批单，顺序固定） | ① 标题（动词+对象+关键数值）② 徽标行（动作类型、不可逆/对外可见、需谁批）③ **必须先看这一句**（最坏后果）④ 影响面/依据/已挂起时长（三小卡）⑤ 逐对象会发生什么（原值→新值、依据）⑥ 证据（必看分区带“已查看”勾）⑦ 备选方案（含后果）⑧ **决定区** |
| 决定区 | 主按钮“批准”、次按钮“退回改写”（原因必选）、“拒绝”；WARN 逐条确认；同意 1 额外勾选“把这一类加入授权清单（仅同意 1）”；未查看必看分区时“批准”禁用并提示缺哪一块 |
| 右栏 | 前置条件当前值（PC-*）、事实快照版本、代批记录 |
| 同意 1 批量 | 单张单内含 N 行，逐行证据可展开；DEGRADING 行默认展开；整单批准前每行均须 `viewed` |
| 挂起 Tab | 挂起原因 + “需要你做什么”（补数据/确认读回/重跑预检…）；不出现倒计时；**挂起不会自动重试**；两个动作「重跑预检」「终止批次」，终止旁写明「已执行部分不回滚」，终止后生成去后台处理清单 |
| VOID | 旧单灰显“已作废”，链接到后继单与 diff |

### SCR-07 上架（v3：批量上架包为主线）

**通道对比条**（A1 逐项照做 / A2 批量上架包（当前）/ B 写接口（未启用）/ C 授权 ERP（未启用））；默认标签页“批量上架包”：批次构成（按末级类目分组、卖家 SKU）+ 五步（生成 → 一次上传 → 失败回收 → 导出文件自动读回 → 审核状态更新）；逐项回填仅在导出文件缺列时使用。主按钮“下载本批上架包”。以下为旧版（逐项照做）规格，保留为兜底：

### SCR-07（旧）上架

| 区域 | 内容 |
|---|---|
| 页首 | 提醒条：通道 A 固定文案；主按钮“复制全部并去后台” |
| 清单卡（一商品一卡，一卡一动作：新建商品） | 字段表：字段名 · 值 · 复制按钮：商品タイトル、商品説明、カテゴリ、ブランド、原産国、販売価格（税込）、在庫（初值）、送料、発送までの日数、返品条件、保証/販売条件、主图/视频（按 SKU 命名的素材包下载）、特商法表示（引用店铺档案） |
| 回填区 | 商品 ID + 后台实际值（标题、价格、库存、类目、图片数、送料、発送日数，可附截图）；提交后即时比对 |
| 读回结果 | 一致 → 绿；关键字段不一致 → 红“读回不一致”，只有“去后台改后重填”与“去后台下架”；非关键字段差异 → Owner 填理由接受（走审批） |
| 末尾确认位 | 运费模板已核对 · （若已开通）加入联盟公开计划 |
| 审核结果 | 人回填：审核中 / 已上线 / 驳回+原因（驳回回到素材） |
| 命中 G0/G1 | **整张清单不可执行**，不是单行置灰；其余 SKU 拆新卡重批 |

不含改价、改库存、下架卡（NV/范围：去后台，仅显示提醒条）。

### SCR-08 授权清单

- 表：规则（动作类型、范围摘要）、状态、到期日、已用/上限、抽检结果、最近使用；右栏：六维度（动作/店铺/类目/价格带/毛利下限/频次与总量/有效期）、代批记录、撤销历史。
- 操作：**收窄**（只给更小选项）、**撤销**（一键、立即、无理由）、复核到期规则；**界面上没有“放宽”按钮**。
- “不可加入”区：列出永不可授权动作并标“这类动作必须由你本人批准”。
