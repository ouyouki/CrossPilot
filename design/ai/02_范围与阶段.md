# 02 · 范围与阶段

## 1. 前提（外部事实，只能接受）与决定（可改）

**前提**

| # | 前提 | 对设计的影响 |
|---|---|---|
| 1 | 平台写接口资格**没有**，也没建过 App；读接口也视为没有 | 本期必须在**零接口**下走通：数据由人导入，上架走执行清单（通道 A）。注册开发者/申请权限是并行轨道，不是前置 |
| 2 | 平台**不提供“创建订单”接口** | 系统里不存在“创建订单”动作 |
| 3 | 店铺是**中国主体 + 跨境直邮 + 日本站 + 自己一家店**（用户 2026-10-19 确认）；保证金 15 万日元（用户确认，官方原文缺） | 到岸成本含国际运费/关税/输入消费税；本土店规则不适用；保证金只用于预警与文案，不当硬闸门 |
| 4 | 日本站跨境店的时效、退货、禁限售、费率、税务口径多数**未核实** | 全部登记为 U-*（§5），实现成“配置项 + 缺失即阻断” |

**决定**

| # | 决定 | 理由 |
|---|---|---|
| D1 | 只做 **Windows PC 浏览器一端**（Chrome/Edge 最新版，基准 ≥1366×768，主用 1920×1080）；手机能打开但不做专门功能，无 App/推送 | 本期运营是一个人坐电脑前，多一个设备口径成本翻倍 |
| D2 | 审批单**不过期作废** | RL-1 |
| D3 | 不写平台的域（订单/售后/广告/达人/客服/资金）= 一条提醒 + 一个跳转 | PR-7 |
| D4 | 多店只预留（`shop_id`），不做跨店功能 | PR-4 |
| D5 | **通道 A（执行清单）是第一天就完整可用的路径**；通道 B（写接口）是适配器槽位，U-1/U-2 关闭后再实现 | 不把“有写接口”当默认假设；清单跑顺 = 把 B 的规格先定好 |
| D6 | 界面语言中文，商品内容日文；日文内容在审批界面旁附**中文回译** | 操作者读中文，必须能核对日文含义（03 §5.4） |

## 2. 阶段

| 阶段 | 内容 | 进入条件 |
|---|---|---|
| **P1（本期）** | 主线：方向卡 → 选品 → 采集 → 素材工厂 → 上架（通道 A）→ 读回核对；审批/授权/审计/设置；每周店铺体检录入；上架结果回填 | — |
| **P1.5** | 通道 B 适配器（写接口上架 + 自动读回 + 24h 一键下架）；只读同步替代手工导入 | U-1、U-2 有平台书面答复，且 P1 通道 A 连续 2 周无 `READBACK_MISMATCH` 未处理项 |
| **P2** | 只读监控与预警（违规分、迟发率、保证金余额自动读取）；上架结果自动回流并给出权重校准建议（人批） | 读接口可用 |
| **P3** | 第二家店：开配置复用；商品级跨店克隆（源店发起 + 逐店差异预演 + 逐店批） | P1 稳定 + 有第二家店 |

## 6. “不做”的统一形态

不做的域在界面上只表现为：**一条提醒 + 一个跳转**（`CAP-OPS-08`）。例如：

| 类型 | 例子 | 系统里长什么样 |
|---|---|---|
| 平台后台已很完善的日常操作 | 改价、改库存、下架、发货、面单、广告调价 | 「建议去后台处理：3 个商品价格低于你的毛利底线」 → 跳转 |
| 真金白银且不可逆 | 退款、提现、保证金、付款周期 | 「保证金可用余额低于预警线」 → 后台处理 |
| 法律/主体级 | 资质提交、关店、申诉、税务申报 | 「证书 12 天后到期」 → 后台续期 |
| 低频重决策 | 履约模式切换、类目扩张 | 本月无需处理 |

**提醒来源仅限**：人工导入数据与每周体检录入。本期**不读取**平台数据，所以提醒也不得暗示“店铺一切正常”（空态文案写“本期未自动检查履约指标”）。
