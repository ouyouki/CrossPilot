# 01 需求 —— #22 候选页可用化 + 同意 1

| 项目 | 内容 |
|---|---|
| Issue | #22 |
| 版本 | 0.1.0 |
| 作者 | 开发 Agent |
| 状态 | 确定 |

## 1. 目的与范围
- 目的:候选页目前只是"看起来对"。这一条让它变成能用的选品入口:真实数据、可勾选、可提交同意 1。
- 做:表格行接 `/api/v1/candidates`;勾选上限 10;提交生成 `ACT-SELECT` 审批单;徽章回显。
- 不做:同意 2、审批中心完整画面、数据库持久化。

## 2. 现状与问题
| No | 现在的做法 | 遇到的问题 | 影响 |
|---|---|---|---|
| 1 | 表格是原型写死的演示行 | 数字不是算出来的 | 无法据此判断 |
| 2 | 勾选没有行为 | 点了没有任何结果 | 选品无法继续 |

## 3. 业务需求
| BR 编号 | 业务上需要能做到什么 | 环节 | 优先级 |
|---|---|---|---|
| BR-22-01 | 从候选里挑几个,提交给"同意 1"等人批 | 选品 → 同意 1 | 高 |

## 4. 功能需求
| REQ 编号 | 需求 | 验收条件 | 画面与 API |
|---|---|---|---|
| REQ-22-01 | 表格行来自接口 | 行数与 `/api/v1/candidates` 一致;毛利与 `costing.compute` 一致 | 候选页 |
| REQ-22-02 | 勾选上限 | 超过 10 个时提示并取消该次勾选;计数正确 | 候选页 |
| REQ-22-03 | 提交生成审批单 | 返回 PENDING 的 `approval_id`;`/api/v1/approvals` 能看到 | `POST /api/v1/approvals/selection` |
| REQ-22-04 | 重复提交幂等 | 同一批再次提交返回 `duplicate=true`,不新建 | 同上 |
| REQ-22-05 | 徽章回显 | 提交后左侧「待批」显示数量 | 外壳 |
| REQ-22-06 | 不可选的候选 | `status=UNKNOWN` 的行没有金额、复选框禁用 | 候选页 |

## 5. 非功能需求
| 分类 | 需求 | 标准 |
|---|---|---|
| 性能 | 提交往返 | 本机 < 300ms |
| 安全 | 只在本机 | 绑 127.0.0.1 |
| 运维 | 内存态 | 重启清空,页面注明 |
