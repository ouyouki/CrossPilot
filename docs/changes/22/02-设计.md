## 1. 后端

| 文件 | 职责 |
|---|---|
| `app/store.py` | 模块级内存状态:`InMemoryApprovalRepo` + `ApprovalsService` + `AuditLog` + `SELECTION_CAP=10` |
| `app/selection.py` | `approvals()` 列待批;`create_selection(ids)` 建 `ACT-SELECT` 单 |
| `app/server.py` | 新增 `GET /api/v1/approvals`、`POST /api/v1/approvals/selection`;错误统一 problem+json |
| `app/main.py` | FastAPI 侧同样两条路由(装了 fastapi 时用) |

为什么用内存:`04` 内核的仓储接口已经有了,但没有数据库迁移。这一条只验证链路,重启清空;页面上标"内存态"。
换成 SQL 时只替换 `store`,处理器不动。

判定边界:`create_selection` **不做**"该不该批"的判断——`ACT-SELECT` 的处置在注册表里固定为 `REQUIRE_HUMAN`,
这里只把人选出的东西变成一张 PENDING 单。

## 2. 前端

| 文件 | 职责 |
|---|---|
| `pages/selection.ts` | 拉接口 → 替换 `.tbl tbody`;勾选上限;提交按钮;toast 与徽章事件 |
| `pages/Candidates.tsx` | 挂载时调用 `mountCandidates()`,卸载时还原原型行 |
| `shell/Shell.tsx` | 监听 `cp:toast` / `cp:approvals-changed`;「待批」徽章改为实时数量 |

保留原型标记与类名(`prod`/`thumb`/`badge`/`num`),只替换行内容;行详情仍用原型的 `d-gen` 模板。

## 3. 关键取舍

| 取舍 | 理由 |
|---|---|
| 提交按钮注入到卡片头部工具区 | 原型那里本来就有"打开待批""筛选"等按钮,位置一致 |
| 不新增画面 | 同意 1 的完整审批界面属 SCR-06,下一个 Issue |
| `UNKNOWN` 行禁用勾选 | 利润算不出来的候选不能进同意 1(INV-10) |
| 幂等用"同 action + 同 subject_key 的未结单" | 与 `06 §7` 的唯一索引同义,先应用层做 |
