# 01 需求 —— #8 最小可跑骨架

| 项目 | 内容 |
|---|---|
| Issue | #8 |
| 版本 | 0.1.0 |
| 作者 | PM Agent(草稿) |
| 状态 | 草稿 |

## 1. 目的与范围
- 目的:让应用先跑起来、能看见,避免埋头做完才发现方向不对。
- 范围(做):FastAPI 骨架、`/healthz`、今日与候选两个只读接口、两屏前端、样例数据、README 启动命令。
- 范围(不做):登录与权限、真实导入、审批动作、数据库、素材与上架。
- 使用者(角色):Operator(看今日与候选)。
- 相关画面与功能:SCR-01 今日、SCR-03 候选列表。

## 2. 现状与问题
| No | 现在的做法 | 遇到的问题 | 影响 |
|---|---|---|---|
| 1 | 只有库代码,没有可运行的应用 | 无法确认画面方向对不对 | 返工风险 |

## 3. 业务需求
| BR 编号 | 业务上需要能做到什么 | 业务流程的环节 | 优先级 |
|---|---|---|---|
| BR-8-01 | 打开应用就知道今天要做什么 | 今日 | 高 |
| BR-8-02 | 看到候选的毛利并展开核对 | 选品 | 高 |

## 4. 功能需求
| REQ 编号 | 需求 | 验收条件 | 画面与 API |
|---|---|---|---|
| REQ-8-01 | 今日页显示待办数、就绪缺项、样例提醒 | 浏览器打开首页能看到这三块,空态不白屏 | `GET /`, `GET /api/v1/today` |
| REQ-8-02 | 候选列表显示样例候选与毛利 | 列表有行,每行显示毛利与数据状态 | `GET /api/v1/candidates` |
| REQ-8-03 | 候选成本分项由 `costing.compute` 得出 | 展开一行,16 项之和与 `compute` 的 results 一致 | 同上 |
| REQ-8-04 | 健康检查 | `GET /healthz` 返回 `{"status":"ok"}` | `GET /healthz` |
| REQ-8-05 | 断网也能启动 | 无网络时按 README 命令能启动并显示样例 | README |

## 5. 非功能需求
| 分类 | 需求 | 目标与标准 |
|---|---|---|
| 性能 | 首屏 | 本机 < 2s |
| 安全 | 只绑 127.0.0.1 | 不对外监听 |
| 易用性 | 一条命令启动 | README 可复制 |
| 运维 | 无外部依赖 | 样例数据在仓库内 |

## 6. 约束与前提
- 成本数字必须来自 `crosspilot.costing.compute`,不得另写算法。
- 持久化、鉴权、真实导入不在本期。

## 7. 术语
| 术语 | 含义 |
|---|---|
| 骨架 | 能跑、能看、能扩展的最小应用形态 |
| 样例数据 | 仓库内的固定 JSON,不是平台事实 |
