## 1. 接缝

两个接缝,测试只打这两个:

1. **HTTP 接口**:`/healthz`、`/api/v1/today`、`/api/v1/candidates`(用 `httpx`/TestClient 或直接调处理器)。
2. **成本数字**:页面里的毛利必须来自 `crosspilot.costing.compute`,不另写算法。

为了在**没有 FastAPI 的环境**里也能跑测试,处理器写成**纯函数**:
`app/handlers.py` 返回普通 dict;`app/main.py` 只做「把 dict 变 HTTP」的薄适配。
这样 CI 不需要装 FastAPI 也能测业务,装了 FastAPI 时走的还是同一份处理器。

## 3. 接口

| 方法 | 路径 | 返回 |
|---|---|---|
| GET | `/healthz` | `{"status":"ok"}` |
| GET | `/api/v1/today` | `{"pending_approvals":int,"readiness":{"items":[...],"missing":[str]},"reminders":[...]}` |
| GET | `/api/v1/candidates` | `{"items":[{"id","title","category","price_jpy","margin","status","cost_items":[...]}]}` |

- `cost_items` 是 `costing.compute` 的 16 项原样输出(含 source/status/severity)。
- 错误统一 `application/problem+json`。
- 只绑 `127.0.0.1`。

## 4. 处理流程

1. 启动 → 读 `backend/data/sample/*.json`(仓库内,断网可用)
2. 每个候选构造 `CostInput`(费率卡取样例)→ `compute()` → 得到 margin 与 cost_items
3. 处理器拼成响应;FastAPI 适配层返回 JSON
4. 前端 `fetch` 这两个接口渲染两屏

## 5. 权限与错误处理

- 不鉴权(只绑本机);样例文件缺失 → 返回空列表 + `notes`,页面显示空态,不白屏。
- 计算失败(例如样例费率卡不完整)→ 该候选 `status=UNKNOWN` 并带 `missing`,不影响其他行。
