## 2. 一个口径修正

原来 `approvals()` 用 `repo.list_open()`,而"未结"按 `06 §7` 的定义包含 `APPROVED`(还没执行)。
但**待批**只应该包含 `PENDING`——`APPROVED` 已经有人签过字了,只是还没执行。

所以加了 `_pending_only()`。这不是妥协,是把两个概念分开:
- **未结**(open):防重复建单、唯一索引用;
- **待批**(pending):界面上"等你批"的清单。

## 3. 接口

| 方法 路径 | 说明 | 错误 |
|---|---|---|
| `GET /api/v1/approvals/{id}` | 单据 + 证据(每个对象带 16 项成本) | 404 |
| `POST /api/v1/approvals/{id}/views` | `{section}` 记录已查看 | 404 / 400 |
| `POST /api/v1/approvals/{id}/decide` | `{decision, version, payload_hash, note?, return_reason_code?}` | 409 `EVIDENCE_NOT_VIEWED`、412 `VERSION_CONFLICT`、403 `ACTION_FORBIDDEN`(退回缺原因) |

`decide` 的 actor 是服务层固定的 `u-operator`(Operator)。本期是单人运行,人不经浏览器登录;
等做登录时,这个 actor 从会话来,函数签名不变。
