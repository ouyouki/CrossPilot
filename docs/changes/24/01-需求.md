# 01 需求 —— #24 审批中心后端(看单 / 批准 / 退回 / 拒绝)

| 项目 | 内容 |
|---|---|
| Issue | #24 |
| 版本 | 0.1.0 |
| 作者 | 开发 Agent |
| 状态 | 确定 |

## 1. 目的与范围
- 目的:同意 1 已经能建单,但没有地方看和批。先把**接口与判定**做对,画面单独一条 Issue。
- 做:`GET /approvals/{id}`、`POST /approvals/{id}/views`、`POST /approvals/{id}/decide`;走 `ApprovalsService.decide`。
- 不做:审批中心画面(下一 Issue)、同意 2、授权代批、持久化。

## 2. 现状与问题
| No | 现在的做法 | 遇到的问题 | 影响 |
|---|---|---|---|
| 1 | 只有 `GET /approvals` 列表 | 看不到对象与证据 | 无法批 |
| 2 | 没有批准入口 | 单据永远 PENDING | 闭环断在这里 |

## 3. 业务需求
| BR 编号 | 业务上需要能做到什么 | 环节 | 优先级 |
|---|---|---|---|
| BR-24-01 | 看清单据后批准/退回/拒绝 | 同意 1 | 高 |

## 4. 功能需求
| REQ 编号 | 需求 | 验收条件 | API |
|---|---|---|---|
| REQ-24-01 | 单据详情带对象与证据 | 每个对象带标题、售价、毛利、16 项成本 | `GET /api/v1/approvals/{id}` |
| REQ-24-02 | 记录"已查看" | 记录后 `viewed` 增加 | `POST .../views` |
| REQ-24-03 | 未看必看证据不得批准 | 409 `EVIDENCE_NOT_VIEWED` | `POST .../decide` |
| REQ-24-04 | 版本不符拒绝 | 412 `VERSION_CONFLICT` | 同上 |
| REQ-24-05 | 批准后状态与审批人 | `APPROVED`,`approver_kind=human` | 同上 |
| REQ-24-06 | 退回必须带预定义原因 | 缺原因 → 拒绝;带原因 → `RETURNED` | 同上 |
| REQ-24-07 | 拒绝 | → `REJECTED` | 同上 |

## 5. 非功能需求
| 分类 | 需求 | 标准 |
|---|---|---|
| 性能 | 详情往返 | < 200ms |
| 安全 | 只接受人的身份 | 服务层 actor 固定为 Operator(登记在案的真人) |

## 6. 约束与前提
- 判定不重写:必看证据、版本、载荷哈希的规则都在 `ApprovalsService.decide` 里。

|---|---|
