## 4. 内存实现 vs 数据库约束（重要）

`06 §7` 的 DDL 尚未编写，也**未在 PostgreSQL 上验证**。本切片用内存对象实现等价语义，对应关系如下；上线前必须由 DDL 再来一遍（且 `06 §7` 的审批人 `CHECK` 需按 `docs/design-gaps.md` D-2 修正）：

| 06 §7 约束 | 本切片对应 |
|---|---|
| 复合外键 `(approver_user_id, approver_kind) → users(id, kind)` + `approver_kind='human'` | `Approval.transition()` 校验 `approver_kind == 'human'`（INV-4 测试） |
| 状态转换触发器查 `approval_transitions` | `state_machine.TRANSITIONS` + `assert_transition()`（INV-2 测试） |
| 未结单部分唯一索引 | `InMemoryApprovalRepo.add/save` 的 open 冲突检查（INV-17 测试） |
| `CAS UPDATE … WHERE status='APPROVED'` | `try_begin_execution()` 持锁比较并切换（INV-17 测试） |
| `CHECK(used_count <= max_uses)` + 原子 `UPDATE` | `GrantEngine.consume()` 持锁计数（INV-21 测试） |
| 审计只 INSERT、链头 `FOR UPDATE` | `AuditLog.append()` 持锁串行 + 哈希链（INV-11 测试） |

## 5. 开发期失败用例与处置（留档）

| 失败 | 原因 | 处置 |
|---|---|---|
| `_pc_payload() takes 2 positional arguments but 4 were given` | 检查器签名不统一，`evaluate()` 统一按 4 参调用 | 统一为 `(snapshot, current, now, guardrails)` |
| `'ApprovalsService' object has no attribute 'service'` | 测试把 `service` 当成 `Harness` 传入 `PayloadGuard` | 守卫改为只依赖 `ApprovalsService` |
| `illegal approval transition: PENDING -> PENDING` | 测试对已提交的单又调了一次 `submit` | 测试改为直接 `decide`，并保留“一年后仍可批”的原意 |
| 判定为 `REQUIRE_HUMAN` 而应为 HOLD（规则抛错但 `requires_facts` 为空） | UNKNOWN 只在“有缺失事实”时转 HOLD | 新增 `rule_unknown → HOLD` 分支（INV-9 更严） |
| 规则库过期的提示被吞成“缺事实” | Gate 用固定文案覆盖了 verdict 的原因 | HOLD 时用 verdict 的原因作 detail（审批界面需要“已过期 N 小时”） |
| `'ToolCall' object has no attribute '__dict__'` | `slots=True` 的数据类不能那样克隆 | 用 `dataclasses.replace` |
