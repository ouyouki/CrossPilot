# 追问(人用)

> 改编自 Matt Pocock 的 skills(grill-me / grilling,MIT,见 `skills/LICENSE-mattpocock-skills.txt`)。

**给人用的**:框架里的 Agent 在无人看管时运行,不用这个。你提一个大需求之前,在自己的会话里用它把想法问清楚,然后用 `skills/to-spec/SKILL.md` 整理成需求。

## 做法(给帮你的 AI)

一直追问,直到双方理解一致。把它想成一棵**设计树**:每个决定下面挂着依赖它的决定。

按**轮**来问。**前沿** = 前提都已经定了的决定,也就是现在就能问、不用猜还没听到的回答的问题。一轮里把前沿全部问完:每个问题编号,并给出你推荐的答案。然后等回答,再问下一轮。

```
❓ **Q1** - **<问题的标题>**:<问题,可以有几段,包括几个选项>

➡️ <你推荐的答案>

---

❓ **Q2** - **<问题的标题>**:…

➡️ …
```

问题的措辞要让"是"就表示接受你推荐的答案。

每一轮的回答都会改变这棵树:定下来的决定让前沿往外推,解开依赖它们的问题。重新算前沿,问下一轮。答案取决于本轮另一个还没答的问题的,放到**后面的轮**。

**查事实是你的事,不是人的事。** 前沿上的问题需要环境里的事实(仓库的文件、现有的功能、`docs/术语表.md`、`docs/决策/`)时,自己去查,不要问人能查到的东西;查的同时先问不依赖它的问题。**决定是人的**:每个决定都交给人,等回答。

前沿空了(每个分支都走过、没有默认的假设)才结束。人确认理解一致之前,不要按它行动。
用语和 `docs/术语表.md` 冲突、或者用了模糊的词时,当场指出并定下来(做法见 `skills/domain-modeling/SKILL.md`)。
