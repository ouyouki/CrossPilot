# 问卷

> 改编自 Matt Pocock 的 skills(to-questionnaire,MIT,见 `skills/LICENSE-mattpocock-skills.txt`)。原版先问用户"发给谁、要什么";本框架里 PM Agent 从 Issue 上的记录判断,人转交前可以改。

把人自己回答不了的事,做成一份**问卷**:人把它交给一个人异步填写,或开会时一起填。对方有人缺少的知识,问卷把它问出来。

## 1. 先弄清两件事(从 Issue、方案、`[提问]` 里判断)

- **发给谁**:对方的角色(只写角色,例「客户的财务负责人」,不写人名)、他知道什么人不知道的东西。这决定问卷的口气和要带多少背景。
- **要拿回什么**:人自己定不了、需要从对方那里拿到的具体决定或事实,列成清单。

判断不了发给谁时,问卷的开头写"建议发给:<角色>(请人确认)"。

## 2. 写问卷

清单里的每一项都要有问题覆盖。放在哪:
- **出方案时(/pickup)**:写到 `docs/changes/<编号>/问卷-<英文短名>.md`,和方案一起提交、推送。
- **回答 `[提问]` 时(/answer)**:不推送(这时可能已经有 PR,推送会让评审和测试的结论失效),把问卷全文写进 `[回答] Q-<编号>-<序号>` 评论里。
问题按重要的在前排(异步时可能只有一次机会);超过几个时按主题分 `##` 小节。
不写客户名、人名、密钥;例子只用样例数据。

```md
# <问卷的标题>

**目的**:为什么有这份问卷、要靠它做什么决定。
**发给**:<角色>   **回答的用途**:<用在哪个需求的哪个决定>

## 背景
一段话,让没参与讨论的对方能答好。够用就行,不要一页。

## 怎么回答
期限和大概的工作量。部分回答、"不知道"也有用:不确定的请标出来,不要跳过。

## <主题>

### <一个问题只问一件事>
_为什么要问:<只在问题可能被误解、或容易被随便回答时写一行>_

>

## 其他
有没有我们没问、但应该知道的?
```

## 3. 交给人

- 在 Issue 写 `[回答] Q-<编号>-<序号>`(出方案时写在「要人回答的问题」里)说明:这个问题要问 <角色>,问卷在 <文件或这条评论>;加 `待人决定`。
- 在「每日计划」写一行:`#<编号> 有问卷要请 <角色> 填:<文件>`。
- 人拿到回答后,在原 Issue 写 `[决定]`(可以把问卷的回答贴进去或写进问卷文件),之后照常推进。
